# 红红子lab (REDKO_LAB)

[![Release](https://github.com/ChimeRED/redkolab/actions/workflows/release.yml/badge.svg)](https://github.com/ChimeRED/redkolab/actions/workflows/release.yml)
[![最新版本](https://img.shields.io/github/v/release/ChimeRED/redkolab)](https://github.com/ChimeRED/redkolab/releases/latest)

一个 **Blender 4.0 ~ 最新版通用的单文件插件**，把一串高频操作变成一次点击，外加一整套界面配色与布局工具：

| 功能 | 说明 |
| --- | --- |
| 🔧 删除所有材质 | 一键清空选中物体的全部材质槽（材质数据块本身保留在文件里） |
| ✅ 应用所有修改器 | 一键把所有修改器烘焙进网格 |
| 🗑 删除所有修改器 | 一键丢弃全部修改器（不烘焙） |
| 🪜 一键楼梯 | 体块整成 0.3 宽 × 0.2 高（长度不变）+ 相对偏移阵列；移动鼠标换方向、滚轮改节数、左键确认 |
| 🔄 一键翻面 | 把选中物体的网格**所有面整体翻转**（法线朝内 ↔ 朝外）；多用户网格先复制成单用户，非网格物体跳过并计数 |
| 🔍 检测是否有反面 | **只读**检查选中物体有没有整体翻面：闭合网格用**有符号体积**（可靠判据），非闭合网格用「质心朝外」启发式并明确标成**「疑似」**；不改网格、不改选择 |
| 👁 一键查看面朝向 | 切换当前屏幕里**所有 3D 视口**的面朝向叠加层（朝外蓝 / 朝内红）：只要有视口关着就全开，全开才全关 |
| 🙈 一键隐藏刀具 | 把目标里**布尔切割用的刀具**物体在当前视图层隐藏（等价于逐个按 <kbd>H</kbd>）。判据按可靠性排优先级：**被布尔修改器引用**（最可靠，会记下谁引用它）> **线框显示且名字像刀具**（交叉验证）> 仅按名字（兜底，报告里明确写「仅按名字推断」）；饼菜单项**不传参数**（按偏好设置走既有目标机制），N 面板另有两个显式目标按钮（选中物体 / 当前集合），只隐藏、不改显示类型、不删物体、不动修改器；恢复用 <kbd>Alt</kbd>+<kbd>H</kbd> |
| 🎨 主题颜色 | 底色 / 图标与文字 / 边框 **分开设置**（每项自带小调色盘 + 自动配文字色 + 对比度检查）+ 调色盘与十六进制自定义色 + 时间线当前帧 + 3 套配色预设（马拉松 建模 低干扰 / 马拉松 浅灰卡 / 死亡搁浅）+ 第 4 个可存的「自定义预设」+ **色相 / 饱和度 / 明度 / 选中几何饱和度** 四个调整滑杆（**只调强调色，且每个预设各自独立**）+ 自定义配色 |
| 🔤 字体设置 | 界面缩放、DPI、自定义界面字体 / 等宽字体、抗锯齿、hinting、线条宽度（写进 Blender 偏好设置） |
| 🖥 页面布局 | 把工作区 + 区域划分存成快照，在新文件里一键还原；也能直接存成启动布局 |
| ↕ 面板顺序 | 拖动调整**本插件自己的面板**在 N 面板里的上下顺序（并列出侧栏现有标签页） |
| 📦 ZML_LAB 一键更新 | 自动扫描源目录里的 **ZML_LAB 压缩包**，把它**剪切**到插件库并替换已安装版本；先备份、装完自动重新启用，**插件设置与快捷键不变**（模块名不一致时直接拒绝） |

三种呼出方式：

1. **饼菜单** —— 默认快捷键 <kbd>Ctrl</kbd>+<kbd>E</kbd>（可改成任意按键）—— 八个方位上分别是
   **左=应用修改器 / 右=一键翻面 / 下=删除材质 / 上=一键楼梯 / 左上=一键选中当前相机 /
   右上=一键隐藏刀具 / 左下=删除修改器 / 右下=一键查看面朝向**（8 个方位全部填满，没有空位）
2. **N 面板** —— 3D 视图 ▸ 侧栏（<kbd>N</kbd>）▸ `红红子lab` 标签页 —— 里面最上面一排是
   **「建模 | 工具 | 主题」** 三个分页按钮（样式参考插件库 ZML_LAB）：
   **建模** = 八个一键功能 + **灰度滤镜**（一键选中当前相机只放饼菜单，不占 N 面板位置）；**工具** = 饼菜单与快捷键 / 插件设置 / 面板顺序；
   **主题** = 主题颜色（控件配色 + 配色预设 + 字体设置）
3. 搜索菜单（<kbd>F3</kbd>）里直接搜「红红子lab」或「REDKO」

> 「插件设置」原来在饼菜单里，已按需求挪到 N 面板；主题颜色也只放 N 面板。
> 「检测是否有反面」只在 N 面板（饼菜单里放不下、也不该抢位置）。
> 「一键隐藏刀具」在 **N 面板 ▸ 建模**（两个显式目标按钮）**和饼菜单右上**（2.22.1 起，
> 饼项不传参数，按偏好设置走既有目标机制）；「灰度滤镜」2.22.1 起**只在 N 面板 ▸ 建模**。
> 这些都有自动化测试盯着（直接解析安装后的 `ui.py` 断言饼菜单就是那八个功能入口、
> 断言灰度滤镜不在饼菜单里、断言检测按钮不在饼菜单里），改坏会立刻失败。

插件列表里显示的名字是 **红红子lab (REDKO_LAB)**，中英文都能搜到。

## 一、安装：一个 zip 通吃 4.0 ~ 最新版

只有一份安装包，从 **[Releases 页面](https://github.com/ChimeRED/redkolab/releases/latest)** 下载
`redkolab-<版本>.zip` —— 每个版本一条永久归档，附件里还有 `SHA256SUMS.txt` 可校验。

本地自己打也可以：`python tools/build_zips.py`，产物在 `dist/`（`dist/` 不入库，安装包一律由 Release 归档）。

| 你的 Blender | 怎么装 |
| --- | --- |
| **4.2 及以上**（4.2 / 4.3 / 4.4 / 4.5 / 5.x） | 偏好设置 ▸ **扩展 / Get Extensions** ▸ 右上角下拉 ▸ **Install from Disk**，选这个 zip；或者**直接把 zip 拖进 Blender 窗口** |
| **4.0 / 4.1** | 偏好设置 ▸ **插件 / Add-ons** ▸ 安装… ▸ **Install from Disk** |

> 同一个包在 4.2+ 的**插件页**也能装（会按传统插件方式加载，功能完全一样），
> 所以无论你习惯点哪个安装按钮都不会翻车。

装完在列表里勾选启用即可。**手动安装**：把压缩包里的 `redkolab/` 整个文件夹拷到

```
<Blender 配置目录>/scripts/addons/
```

Windows 一般是 `%APPDATA%\Blender Foundation\Blender\<版本>\scripts\addons\`。

### 为什么一个包能通吃

包里的结构只有一种，源码只有一份：

```
redkolab/
    __init__.py            <- 同时带 bl_info（传统插件元数据）
    blender_manifest.toml  <- 扩展清单（4.2+ 读这个）
    compat.py
    ops.py
    ui.py
```

4.2+ 的扩展安装器既能读根目录的清单、也能读单层目录里的清单；而 4.0/4.1 的传统安装器
只认「和模块同名的顶层目录」。把代码和清单一起放进 `redkolab/`，两种安装器就都满足了。

这是实测比出来的，不是猜的：

| 包内布局 | 4.0/4.1 插件页 | 4.2+ 插件页 | 4.2+ 扩展页 |
| --- | --- | --- | --- |
| 代码放根目录 + 目录副本 | 可以 | **报错** | 可以 |
| **只有目录（本包采用）** | 可以 | 可以 | 可以 |

> 根目录带 `__init__.py` 的包会被 4.2+ 的插件页安装直接拒绝
> （`ZIP packaged incorrectly; __init__.py should be in a directory`），
> 这是 Blender 对扩展包的固有行为，不是本插件的问题。

## 二、使用

**前提**：物体模式 + 选中至少一个物体。没有选中任何物体时，会自动作用在**活动物体**上。

### 饼菜单

在 3D 视图里按 <kbd>Ctrl</kbd>+<kbd>E</kbd>，八个按钮按下面的方位摆（8 个方位全满）：

```
                        上：一键楼梯
左：应用所有修改器                              右：一键翻面
                        下：删除所有材质
        左上：一键选中当前相机              右上：一键隐藏刀具
        左下：删除所有修改器    右下：一键查看面朝向
```

方位由**往饼菜单里加东西的先后**决定，跟坐标无关：

| 顺序 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 方位 | 左 | 右 | 下 | 上 | 左上 | 右上 | 左下 | 右下 |

所以想挪按钮只能改 `ui.py` 里 `HHZ_MT_pie.draw()` 的行序。**饼菜单只有 8 个方位，现在已经全满**
（2.17.0 之前右上留空时是用 `pie.separator()` 占位顶住的 —— 占位项同样占一个方位序号，
少顶一个后面的按钮就会整体前移、跑错方位；2.22.1 起右上常驻「一键隐藏刀具」，
**灰度滤镜已经从这个位置挪到 N 面板 ▸ 建模**，以后要再加功能得先腾一个槽位出来）。

**饼菜单项不传参数**：右上那个「一键隐藏刀具」调用算符时**不带 `target_mode`**，算符默认值是
`'PREF'`（按偏好设置）—— 就是项目既有的目标机制（`compat.get_target_objects`：选中的物体，
没选中时是活动物体），和「应用修改器 / 删除材质」这些饼项走的是同一条路。N 面板里那两个
按钮才显式传 `SELECTED` / `COLLECTION`。

（原来的「插件设置」入口已挪到 N 面板的「插件设置」面板；「检测是否有反面」只在 N 面板。
饼菜单里那 8 个算符与图标自 2.18.0 起一字未变，2.22.1 只换了右上这一格。）

**一键选中当前相机**（饼菜单左上）选中**你当前正在通过它看场景的那台相机**：

| 当前视角 | 选中的是 |
| --- | --- |
| 3D 视口正在用**相机视角**（按 <kbd>Numpad 0</kbd> 进入，或视口有自己的相机覆盖） | **该视口正在看的那台相机**（`space_data.camera`） |
| 自由视角 / 用户视角 / 不在 3D 视口 | **场景活动相机**（`scene.camera`，也就是按 <kbd>Numpad 0</kbd> 会进入的那台） |
| 两者都没有 | 提示「当前没有可用的相机」，什么都不改（返回 `CANCELLED`，不报错） |

它只改**选择**：先把当前视图层里的物体全部取消选择，再把相机设为唯一选中物体和活动物体
（用数据 API，不依赖界面上下文），可 <kbd>Ctrl</kbd>+<kbd>Z</kbd> 撤销。相机被隐藏或选不上时
**如实报告**「当前相机被隐藏，无法选中」，绝不假装选中成功。

> 注意：<kbd>Ctrl</kbd>+<kbd>E</kbd> 在**编辑模式**下是 Blender 自己的「边」菜单，
> 模式专用键位的优先级更高，所以饼菜单在编辑模式下不会弹出（物体模式下正常）。
> 想在任何模式都能用，可以在插件偏好设置里换一个不冲突的键。

### 灰度滤镜（N 面板 ▸ 建模，一键切换）

**位置**：2.22.1 起在 **N 面板 ▸ 建模**，与「一键翻面 / 检测反面 / 查看面朝向 / 隐藏刀具」
同一个 column（**没有新增面板**，全插件只有这一处按钮；2.18.0 ~ 2.22.0 它占的是饼菜单右上那一格，
2.22.1 把那一格换成「一键隐藏刀具」）。点一下画面变黑白，**再点一下完全恢复原状**，
可 <kbd>Ctrl</kbd>+<kbd>Z</kbd> 撤销。

**它是怎么做到的**：Blender **没有**原生的「视口灰度开关」—— 实测
（4.0.2 与 5.2.2 各跑一遍，读数见第四节）`View3DShading` / `View3DOverlay` 里
**没有任何** gray / bw / mono / desatur 属性；色彩管理曲线的 `curves` **只有 4 条**
（Composite / R / G / B，读不到通道名、也不支持新增），**没有 Saturation(S) 通道**；
`ColorManagedViewSettings` 上**也没有** `saturation` 标量。

所以本功能用的是 Blender 内置的色彩管理 Look **`AgX - Greyscale`**
（OCIO 配置里 `process_space: AgX Log` 的**真灰度** —— 一个 Rec.709 亮度权重矩阵，
输出 R = G = B）。实测两版都能写、都能读回，F12 渲染出来的中心像素
`(0.4549, 0.4549, 0.4549)` —— **spread = 0**，是真的完全去色。

| 你会看到 | 说明 |
| --- | --- |
| 点一下 | 报告「已开启灰度滤镜（N 个场景）；**注意：这也会影响最终渲染输出**」 |
| 再点一下 | 报告「已关闭灰度滤镜，N 个场景的原始 Look 已还原」 |
| 原本 Look 不是 None（比如你设过 `AgX - Punchy`） | 开之前先把原值记在场景上，关的时候**还原成原来那一个**，不是无脑置 `None` |
| 文件里有多个场景 | 每个场景各记各的原值，关的时候逐个还原 |
| 没有场景 / 没有可用场景 | 提示「当前文件里没有可用场景，无法切换灰度滤镜」，返回 `CANCELLED`，**不抛异常** |

> ⚠️ **它会影响最终渲染输出** —— `look` 是**显示变换（display transform）**的一部分，
> 视口显示、F12 渲染、渲染动画都会一起变灰，**不是「只作用于视口」的预览开关**。
> 所以每次执行都在报告里明说，绝不偷偷改渲染；关掉之后渲染立刻恢复原样
> （实测：关掉后 F12 中心像素逐位等于开之前的值）。
>
> 这个副作用是**取舍**而不是疏忽：唯一真正「只影响视口」的路子是往用户的合成器塞一个
> `CompositorNodeRGBToBW` 再打开视口合成器（`View3DShading.use_compositor`），
> 但那要动用户的 `scene.use_nodes` 和整棵合成树（5.x 的树还搬到了
> `scene.compositing_node_group`），代价远大于收益，**没有采用**。
>
> 同一份灰度状态也**不会**写进偏好设置：它存在场景上（`scene["hhz_grayscale_filter"]`），
> 所以跟着 .blend 走、跟着撤销走，不新增任何设置项。

### 一键楼梯（模态）

选中一个**体块**（立方体之类），点「建模」页的 **一键楼梯** 或按饼菜单的 **一键楼梯**，
然后：

| 操作 | 效果 |
| --- | --- |
| 移动鼠标 | 按方向换阵列方向：**右** `(1,0,-1)` / **左** `(-1,0,-1)` / **上** `(0,1,-1)` / **下** `(0,-1,-1)`；`z` 恒为 `-1`（楼梯往下走），**体块朝向也跟着换** |
| 滚轮上 / 下 | 楼梯节数（阵列数量）`+1` / `-1`，范围 1~500 |
| 左键 | 确认（保留体块尺寸与阵列） |
| 右键 / <kbd>Esc</kbd> | 取消，体块尺寸恢复原样、阵列删掉 |

尺寸与阵列约定：

* **高度（Z）恒为 0.2 m**；
* **沿阵列方向的那条水平边 = 0.3 m**，另一条水平边**保持选中前的尺寸**：
  * 左右方向 → **X = 0.3**、`Y` 不变
  * 上下方向 → **Y = 0.3**、`X` 不变
* 用的是 **Array 修改器 + 相对偏移**（`use_relative_offset`）—— 相对偏移是「系数 × 该轴尺寸」，
  所以系数 `(1, 0, -1)` 每级往 `+X` 挪 0.3 m、系数 `(0, 1, -1)` 每级往 `+Y` 挪 0.3 m，
  两种都是往下 0.2 m —— **改尺寸不用改系数**，方向一换体块会按新轴向重新整型
  （另一条水平轴回到你选中它时的尺寸）；
* 阵列是**活的修改器**（名字叫「红红子lab 楼梯」），随时能改节数/系数，
  想烘成实体就点「应用所有修改器」；重复点一键楼梯会**复用**同一个修改器，不会越堆越多；
* 屏幕左下角的状态栏会实时显示「楼梯 N 节 方向」。

> 单位是米，所以体块尺寸按 **Blender 单位**算（默认场景 1 单位 = 1 m；如果你的场景单位不是米，
> 0.3 / 0.2 就是 0.3 / 0.2 个场景单位）。
>
> 自动化测试覆盖：方向→系数映射（含位移太小时不换方向）、方向→轴向（左右 X / 上下 Y）、
> 尺寸换算（阵列轴 0.3、另一条水平轴保持选中前尺寸、Z 恒 0.2）、节数上下限、
> 真实的体块跑一遍（左右与上下两种朝向都验：尺寸、相对偏移、节数、
> **每级位移正好 0.3 m 与下降 0.2 m**、换方向后另一条轴回到原尺寸、重复调用不新增修改器、能删掉）。
> 模态交互本身（鼠标/滚轮手感）无头环境测不了，需要你在 Blender 里拖一下。

### 一键翻面 / 检测是否有反面 / 一键查看面朝向

这三个是一组：**翻面**负责改，**检测**负责找，**查看面朝向**负责肉眼确认。

| 功能 | 在哪 | 做什么 |
| --- | --- | --- |
| **一键翻面** | 饼菜单「右」+ N 面板 ▸ 建模 | 把选中物体（没选中时是活动物体）的网格**所有面整体翻转** —— 法线朝内 ↔ 朝外 |
| **检测是否有反面** | 只在 N 面板 ▸ 建模（紧挨翻面按钮） | **只读**检查：报告选中物体里有没有整体翻面的，不改网格、不改选择 |
| **一键查看面朝向** | 饼菜单「右下」+ N 面板 ▸ 建模 | 切换当前屏幕里**所有 3D 视口**的面朝向叠加层（朝外蓝 / 朝内红） |

### 一键隐藏组里的所有刀具（2.22.0；2.22.1 起同时在饼菜单右上）

HardOps / Boxcutter 那一类工作流里，**刀具 = 被拿来布尔切割别的物体的那个物体**，
切完通常只剩**线框显示**。所以这里的「刀具」**不是靠名字猜的**，判据按可靠性排优先级：

| 优先级 | 判据 | 怎么认 | 说明 |
| --- | --- | --- | --- |
| **A（最可靠）** | 被**任何布尔修改器**引用 | 扫每个物体的 `modifiers` 里 `type == 'BOOLEAN'` 的项：`operand_type == 'OBJECT'` 取 `mod.object`，`'COLLECTION'` 取 `mod.collection.objects` 里每个物体 | 名字改成什么都跑不掉；同时记下「**谁引用它**」，报告里能看到依据 |
| **B（交叉验证）** | 线框显示 **且** 名字含关键词 | `display_type == 'WIRE'`（或 `show_wire == True`）**且** 名字含 `cutter` / `bool` / `刀具` / `cut`（不区分大小写） | 这条最贴近「切完变线框」的实际状态 |
| **C（兜底）** | **仅名字**匹配 | 同上关键词，但物体不是线框、也没有布尔引用 | **只在前两条都没命中时才用**，报告里必须标「**仅按名字推断**」——它只是推断，不是结论 |

三种目标，**同一个算符的三种调用**（没有新增任何设置项 / 面板 / 开关）：

| 入口 | 传的 `target_mode` | 目标 | 用在什么时候 |
| --- | --- | --- | --- |
| **饼菜单右上**（2.22.1 起） | **不传**（默认 `PREF` = 按偏好设置） | 项目既有的目标机制：选中的物体，没选中时是活动物体 | 想跟「应用修改器 / 删除材质」这些饼项用同一套目标时 |
| **一键隐藏刀具（选中物体）**（N 面板 ▸ 建模） | `SELECTED` | 选中的物体（没选中时是活动物体） | 只处理这一批物体里的刀具 |
| **一键隐藏刀具（当前集合）**（N 面板 ▸ 建模） | `COLLECTION` | 当前高亮的集合（Outliner 里选中的那一格，`context.collection`）**及其所有子集合** | 「组」就是集合：整组里的刀具一次收掉，不受选择影响 |

> `PREF` 不是第三种「找刀具的地方」：算符把它解析成 `SELECTED`（纯函数 `ops.cutter_effective_mode`），
> 也就是走 `compat.get_target_objects`。这样饼项不必带任何参数，和其余七个饼项完全一致。

* **只隐藏**：对识别出的刀具调用 `obj.hide_set(True)`（当前视图层，等价于逐个按 <kbd>H</kbd>）。
  **不改显示类型、不删物体、不动修改器、不改选择**。
* 报告形如「已隐藏 N 个刀具：被布尔修改器引用 X 个、线框+命名 Y 个、仅按名字 Z 个；
  跳过非网格 M 个、已在隐藏集合 K 个、失败 F 个」；只按名字推断的那部分会单独加一句说明。
* 一个都没找到 → 提示「`选中物体`里没有找到刀具（依据：布尔修改器引用 / 线框+命名）」并返回 `CANCELLED`，**不隐藏任何东西**。
* 带 `UNDO`，<kbd>Ctrl</kbd>+<kbd>Z</kbd> 可撤销。
* **恢复**：<kbd>Alt</kbd>+<kbd>H</kbd>（`显示全部`）会把隐藏的刀具重新显示出来 —— 注意它会一起显示**这一视图层里所有**被隐藏的物体。

> 一句话用法：N 面板 ▸ **建模** ▸ 「一键隐藏刀具（当前集合）」处理整组；想只处理某几个物体就
> 先选中它们、点「（选中物体）」或者直接用饼菜单右上那一格（按偏好设置 = 选中物体）。恢复按 <kbd>Alt</kbd>+<kbd>H</kbd>。

### 一键选中当前相机

饼菜单**左上**（2.17.0 起）。它选中**你当前正在通过它看场景的那台相机**，不一定是
`scene.camera` —— 3D 视口可以有自己的相机覆盖，那时两者不是同一台。

| 当前视角 | 选中的是 | 报告 |
| --- | --- | --- |
| 3D 视口处于**相机视角**（<kbd>Numpad 0</kbd> 进入，或视口设了自己的相机）且该视口的相机有效 | `space_data.camera` —— **你正在看的那台** | 「已选中当前视角使用的相机：<名字>（视口相机）」 |
| 自由 / 用户视角、不在 3D 视口（含无头环境） | `scene.camera` —— 场景活动相机 | 「已选中当前视角使用的相机：<名字>（场景活动相机）」 |
| 两者都没有 | 什么都不做 | 「当前没有可用的相机」，返回 `CANCELLED`（**不抛异常**） |

解析顺序固定为「**先看视口是否处于相机视角 → 再看该视口的相机是否有效 → 最后回退场景活动相机**」，
写在一个**不碰 `bpy` 的纯函数** `ops.resolve_view_camera()` 里，所以无头环境能逐条穷举。

它只改**选择**，不改任何数据：先把当前视图层里的物体全部取消选择，再把相机设为唯一选中物体
和活动物体（走 `select_set()` 数据 API，**不用**需要界面上下文的 `bpy.ops.object.select_all`），
带 `UNDO`，<kbd>Ctrl</kbd>+<kbd>Z</kbd> 可撤销。报告成功前会用 `select_get()` **校验真的选中了**：
相机被隐藏 / 不在当前视图层的可见集合里 / Blender 拒绝选择时，如实报告「当前相机被隐藏，无法选中」
之类的原因并返回 `CANCELLED`，**绝不谎报成功**。

> 自动化测试覆盖：纯函数五种组合（视口相机有效且相机视角 / 相机视角但视口相机为空 →
> 回退场景相机 / 非相机视角 / 两者都空 → `None` / **视口相机与场景相机不同 → 必须返回视口相机**）、
> 运行时（无头走回退分支：只有相机被选中且是活动物体）、无相机（`CANCELLED`、不抛异常、不动原有选择）、
> 相机隐藏（如实报告）、收尾清理。
> **未覆盖**：GUI 下「视口相机覆盖 != 场景活动相机」这一支只由纯函数断言覆盖，
> 没有在真实图形界面里点过（无头环境构造不出该状态）。

**翻面的实现方式**：用 `bmesh.ops.reverse_faces` **原地**翻转每个面的顶点顺序，
**不会进入编辑模式**（不打扰你、也不会踩编辑模式的快捷键）。三条边界：

* **多用户网格**（两个物体共用一份网格数据）先**复制成单用户**再翻 ——
  所以只有目标物体变，另一个物体的网格**不会被连带改掉**；
* 非 Mesh 目标（Empty / 灯 / 曲线……）**跳过并计数**，不会报错中止其它物体；
* UV / 顶点组 / 材质槽都不动。**注意**：UV 是「每个面的每个角」存的，面缠绕反过来之后，
  **每个角在列表里的先后顺序会跟着重排**（点到点的贴图位置不变，但逐个角的顺序变了）；
  自定义拆分法线数据同理，方向会跟着面一起翻过去。需要保留原样时先备份文件。

报告形如「已翻面 N 个 / 跳过 M 个（非网格）（共 K 个面）」，
多用户数据被复制时会额外提示。算符带 `UNDO`，<kbd>Ctrl</kbd>+<kbd>Z</kbd> 可以撤销。

**检测的判据（以及它到底有多可信）**：

| 网格情况 | 判据 | 结论可信度 |
| --- | --- | --- |
| **闭合网格**（每条边恰好被两个面用） | **有符号体积**：外向法线的闭合网格体积为**正**，整体翻面后为**负** | ✅ **可靠结论**：报「整体翻面」/「正常」 |
| **非闭合网格**（开口壳、单张面、碎面……） | 「**质心朝外**」启发式：统计法线指向质心的面（内指面）占比，过半就报可疑 | ⚠️ **只是「疑似」**，不得当成确定结论 |
| 闭合但体积≈0（自相交壳等） | 体积判不出方向，退回上面的启发式 | ⚠️ **「疑似」** |
| 空网格 / 没有面 / 非 Mesh | —— | 跳过并计数 |

> **为什么非闭合只能是「疑似」**：一个有符号体积都没有的开口壳根本不存在严格的内外之分。
> 「质心朝外」在整体翻面的空心壳、法线一致朝内的球上很好用，但**凹壳（L 形、甜甜圈）里
> 本来就可能有过半的面「朝着质心」→ 误报**；平面 / 单层结构更是没有内外可言。
> 所以它只用来**提示你去看一眼**，不下结论。

报告与系统控制台：状态栏给汇总「检测 N 个：整体翻面 X 个 / 疑似 Y 个 / 正常 Z 个 / 跳过 W 个」，
并**逐个物体** `print` 到系统控制台（物体名 + 判据 + 有符号体积值或内指面比例）。
检测判据本身是**纯函数**（输入顶点坐标 + 面索引），所以无头环境也能完整验证。

**推荐用法**：先点 **「检测是否有反面」** 定位到底是哪个物体可疑（控制台里有名字）→
再点 **「一键查看面朝向」** 用蓝/红肉眼确认一眼 → 确认是反的就点 **「一键翻面」**。
一次点击即可看/收起：只要有视口是关着的就全部打开，全部已打开才全部关闭。

> 自动化测试覆盖：纯函数判据（外向 +8 / 反向 -8、闭合 vs 非闭合、空数据、零体积）、
> **翻面 → 检测 的往返**（朝内立方体检测报「整体翻面」→ 翻面 → 再检测变「正常」→ 再翻又变「翻面」）、
> 多物体（正常 + 翻面 + 非网格）的计数与汇总、**多用户网格不连带**、`UNDO`、
> 饼菜单 7 项与 N 面板按钮相邻性、面朝向切换纯函数（空 / 全开 / 全关 / 混合）。
> **未覆盖**：真实界面里视口是否真的渲染成蓝/红（自动化只看开关值有没有被正确改写）。


### N 面板：三个分页（建模 / 工具 / 主题）

3D 视图 ▸ 按 <kbd>N</kbd> ▸ `红红子lab` 标签页。**标签页里最上面一排就是分页按钮**：

```
┌─────────┬─────────┬─────────┐
│  建模   │  工具   │  主题   │      ← 无标题栏的一行等宽按钮，点了只显示该页
└─────────┴─────────┴─────────┘
```

| 页 | 放的东西 |
| --- | --- |
| **建模** | 八个一键功能（删材质 / 应用修改器 / 删修改器 / **一键楼梯** / **一键翻面** / **检测是否有反面** / **一键查看面朝向** / **一键隐藏刀具**，后四个按钮相邻）+ **灰度滤镜**（2.22.1 起从饼菜单挪到这里，同一个 column）+ 「选中 N 个物体 材质槽 X 修改器 Y」+ 「呼出饼菜单」按钮 |
| **工具** | 饼菜单与快捷键、插件设置、**页面布局**、面板顺序（拖动排序） |
| **主题** | 主题颜色（控件配色 / 自定义配色 / 配色预设）+ **字体设置** |

做法参考了插件库里 **ZML_LAB（椎木兰LAB）** 的分页样式，机制完全一样（代码自己写的）：

* 「当前页」是挂在 `WindowManager` 上的一个枚举，**每个窗口各记一份**；
* 标签条是一个 `bl_options = {'HIDE_HEADER'}`、`bl_order = 0` 的面板，只画一行
  `row.prop(..., expand=True)`（`scale_y = 1.35` 加高）；
* 每个功能面板在自己的 **`poll()`** 里判断当前页 —— 不属于本页的面板 Blender 直接不画，
  所以整套功能仍然只占侧栏的**一个**标签页，标签页栏不会变乱。

> 自动化测试覆盖：三页名字与顺序、`WindowManager` 属性已注册到 RNA、
> **切到每一页时 5 个面板的 `poll()` 分别返回什么**（共 15 条断言）、标签条无标题/固定最前/同标签页。

### 主题颜色（N 面板 ▸ 主题 页）

改的是**可互动的控件颜色**，不是工作区/视口配色。每一项都是**分开设置**的：

| 第一级下拉里的分组 | 管的是 |
| --- | --- |
| **按钮 底色** | 按钮的本体颜色（普通按钮 / 工具按钮 / 单复选 / 开关 / 数字框 / 文本输入框 / 菜单 / 饼菜单 / 标签页 / 列表 / 分组框……） |
| **按钮 文字与图标** | 按钮上的**字和图标**颜色（默认浅灰） |
| **按钮 边框** | 按钮的描边 |
| **按钮 选中底色 / 按钮 选中文字 / 按钮 选中边框** | 被选中/按下时的那一套（默认那个蓝） |
| **按钮 高亮** | 滑块、进度条填充、列表高亮条 |
| **图标颜色** | 大纲视图等处按类型上色的图标（物体 / 修改器 / 集合 / 文件夹……） |
| **时间线 当前帧** | 时间线 / 摄影表 / 曲线编辑器 / NLA / 序列 / 影片剪辑 / 图像编辑器 / 3D 视图的**当前帧**指示色与时间轴底色 |
| **状态 / 面板（5.x）/ 视口 / 节点 / 动画** | 已修改、动画、关键帧、驱动器、被覆盖；面板色；视口背景、网格、线框、选中物体…… |

用法：

1. **两级下拉选颜色项**：先在**第一级**选一个**分组**（短词，例如「按钮 底色」「视口」「图标颜色」），
   **第二级**就只列这一组里的项（每组几项到二十几项，标签不再重复拼分组名）——
   一次要画的长列表被拆成两个短列表，弹出框**结构上不再需要截断**
2. 拖颜色选择器 —— **实时生效**
3. 选择器下面有**一行明文读数**（`当前值 #545454  R 0.329  G 0.329  B 0.329`），
   即使下拉框本身显示异常，也一眼能看出选了什么
4. **自定义颜色**：调色盘里挑一个色，或直接填 `#RRGGBB`（填了会自动同步到调色盘），
   再点 **「应用颜色」**
5. 不满意就点 **「恢复本项」** / **「恢复本组」** / **「全部恢复」**（三个范围语义不同，见下）
6. 面板上会实时显示 **「本组 N 项有默认值，已改动 M 项」** —— 如果显示"都还是出厂值"，
   那按恢复当然看不出变化（这不是按钮坏了）
7. **分开设置**：见下一节，每一项旁边都有自己的小调色盘
8. **自定义配色**：起个名字点 `+` 就把当前全部颜色存下来，之后下拉里选中它 → 「套用」/「删除」
9. 满意后点 **「保存到偏好设置」**，否则重启会还原

#### 分开设置：底色 / 图标与文字 / 边框

「控件颜色分开设置」这一块就是解决**"底色统一之后按钮上的图案和字看不清"**的：

1. 先在上面选一个**控件家族**（普通按钮 / 工具按钮 / 菜单项 / 标签页 / 列表行 / 进度条……）
2. 下面**逐项列出该家族的每个颜色，每项右边都有一个小调色盘**，可以直接拖：

| 面板上的行 | 管什么 |
| --- | --- |
| 底色 | 按钮本体颜色 |
| **图标与文字** | 按钮上那些**图标和文字**的颜色（看不清就是这一项要提亮/压暗） |
| 边框 | 描边颜色 |
| 选中底色 / 选中文字 / 选中边框 | 被选中、按下时的那一套 |
| 高亮条/滑块 | 滑块、进度条填充、列表高亮条 |

3. **「自动配文字色」**：按底色的亮度自动挑深色字或浅色字（常态与选中各配一次），
   一键解决看不清的问题；「从当前主题读回」用来在别处改过主题后同步面板
4. 面板底部会**实时检查对比度**：如果某个家族的文字与底色亮度差太小，
   会直接标红提示「字会看不清」，正常则显示"文字与底色的对比度正常"
5. **3 套配色预设也已经成对配好**每个家族的底色与文字色（这个检查会盯着它：
   测试里逐家族断言对比度差 ≥ 0.3，任何一个家族配错都会立刻失败）

> 「恢复本项 / 本组 / 全部」的区别：本项只动你当前选的那一个颜色；本组动当前分组里的全部
> （例如「按钮 边框」这一组的所有描边）；全部则是有出厂默认值的那 60+ 项一起回厂。
> 只有 **4.0.2 与 5.2.2 实测一致**的项才记录默认值，5.x 专属项不记录，避免把 5.x 的默认值套到 4.0 上。

  `user_interface.editor_outline` / `editor_outline_active`；
* 文字色默认**按底色亮度自动挑**（深底配浅字、亮底配深字），也可以关掉自动、手动指定；
* 当背景用的那几项（大纲选中行等）会自动用**调暗的选中色**，免得浅色文字压在亮底上看不清。

#### 配色预设

预设一共 **3 套内置 + 1 个自己存的**，在 N 面板 ▸ 主题 页的 **「配色预设（按钮 / 状态 / 当前帧）」**
框里点对应的按钮就套用（三套内置各一个按钮，第 4 个是「自定义预设」；
下面依次是**四个调整滑杆**、「按当前调整重新套用」和「保存当前为自定义预设」）：

| 预设 | 定位 | 主强调色 |
| --- | --- | --- |
| **马拉松 建模 低干扰** | 长期建模的低干扰档：近黑面板 + 压到几乎看不见的边框，黄绿只落在当前选中 / 活动的东西上，不铺开 | 酸性黄绿 `#D6F32B` |
| **马拉松 浅灰卡** | 浅灰纸面高对比档：照着实拍图的浅灰任务卡做的浅灰底 + 近黑字，选中块仍是酸性黄绿 | 酸性黄绿 `#D6F32B` |
| **死亡搁浅** | 冷色工业终端档：冷炭黑底 + **蓝为主强调** + **橙只做点缀**（见下一小节） | 蓝 `#4B7FA8` |
| **自定义预设** | 你自己存的第 4 套：点「保存当前为自定义预设」把**当前预设 + 当前调整**固化下来，之后一键套用 | 由你决定 |

##### 四个调整滑杆（只调强调色，且每个预设各自独立）

四个滑杆**只作用于「强调色集合」**，也就是"变成颜色"的那些地方 —— 当前选中 / 活动的按钮
（每个控件家族的选中底、选中边框、高亮条与滑块）、文本与列表的选中底、活动面板标题、
各编辑器的全局选中高亮（大纲 / 文件浏览器 / 属性 / 信息 / 控制台 / 编辑器图标）、
时间线当前帧、以及**视口里被选中的几何**。**背景、文字、边框、网格线一条都不动。**

这四个值**按预设各存一份**（3 套内置预设 + 「自定义预设」，固定 4 个槽位）：
套用某套预设后，滑杆自动显示**它自己存的那一组值**；调 A 预设的滑杆，B 预设一个字都不变。

| 滑杆 | 范围 | 默认 | 作用 |
| --- | --- | --- | --- |
| **色相** | -180° … +180° | 0°（原样） | 把当前预设的**强调色**整体转一个角度（-180 与 +180 等价）；纯灰（饱和度 0）不受影响 |
| **饱和度** | 0% … 200% | 100%（原样） | `t ≤ 100%`：`S' = S × t`；`t > 100%`：`S' = S + (t-1) × (1-S)`，**200% 正好推到纯色**；纯灰在任何取值下都保持纯灰 |
| **明度** | 0% … 200% | 100%（原样） | `V' = clamp(V × t, 0, 1)`，同样只落在强调色上 |
| **选中线 / 面 饱和度** | 0% … 200% | 100%（原样） | **只作用于视口里被选中的几何**（活动元素 / 顶点 / 边 / 面 四条路径），语义与上面那条饱和度一样 |

* **每个预设各存一份**：四个值不是全局一份，而是按预设分开存（`theme.py` 里
  `preset_adjust_hue` / `preset_adjust_saturation` / `preset_adjust_value` /
  `preset_adjust_selection` 四个 `FloatVectorProperty(size=4)`，分量下标 = 预设槽位；
  面板用 `index=槽位` 直接画）。
  所以"套用 B 会自动显示 B 那一组"是结构上成立的，不靠同步、也不会互相污染；
  默认（0 度 / 100% / 100%）下整表与预设**逐项位级相同**；
  还没套过任何预设时（`last_preset` 为空、拼错、或指向早期版本已删除的预设），
  四个滑杆按**第一套内置预设**（马拉松 建模 低干扰）显示，拖它也就是把那一套按新参数
  套上 —— 与「按当前调整重新套用」的兜底规则一致，且槽位**永远**夹在 0…3；
* **属性名与 2.14.0 的标量名不同**（2.15.1 热修，见下面的「2.15.0 事故」）：
  旧 userpref 里那四条同名条目不再被任何属性读取，所以升级后这四个值从**干净的默认值**
  开始；你之前调过的值需要重新调一次（这不是数据丢失，是那四条旧条目本来就已经读不出正确值）。
  任何入口（打开主题页 / 拖滑杆 / 套用预设）都会做一次**幂等的分量归一化**：
  非有限、越界、非规格化（如 `4.2039e-45`）的分量一律写回中性值 ——
  **已经坏掉的机器装上 2.15.1 即自动恢复，不需要清偏好设置**；
* **集合外的路径是"原对象直接沿用"**：不是"算出来刚好一样"，而是那些键在结果里仍指向
  原来那个颜色元组。有断言逐项核对（三套预设各有 86~115 条护栏路径 × 6 组参数，
  外加真主题里 11 条代表路径的端到端核对）；
* **反复拖不会累积**：每次都是从**预设表**（或你存下来的自定义预设）重算，所以拖到 60% 再拖回 100%
  就是原样，不会越调越灰；
* 「**按当前调整重新套用**」= 用当前预设自己那四个值重新算一遍；
* 「**保存当前为自定义预设**」= 把当前预设的**底表**存成第 4 套，并把当前四个调整值
  **一起固化进「自定义预设」自己的槽位**（同名覆盖，**复用既有的自定义配色存储**，
  不新增配置文件 / 设置项 / 面板）。所以之后套用它 = 底表 + 它自己那份调整 =
  保存当时看到的颜色，**既不会叠加第二次、也不会累积**；源预设的那一份一字不动。
  从没保存过时点「自定义预设」，会明确提示先去保存，而不是莫名失败。

##### 2.15.0 事故：升级后滑杆变 0 / 4.2e-45、所有预设纯黑（2.15.1 已修）

**现象**（用户实测）：从 2.14.0 升到 2.15.0 后，四个滑杆显示
`色相 0.00 / 饱和度 4.2039e-45 / 明度 0.00 / 选中线面饱和 0.00`，
拖任意一个滑杆都一样，套用任何预设整张主题变纯黑。

**根因**（4.5.14 沙箱里用真 2.14.0 包逐级复现）：2.15.0 把 2.14.0 的四个**标量**
`preset_hue` 等改成了 `FloatVectorProperty(size=4)`，却**沿用了同一个属性名**。
载入那份旧 userpref 时，Blender **既没有**把旧标量映射进来、**也没有**套用新默认值，
四个向量的 16 个分量读到的是**未初始化内存**（实测 `7.1613` / `4.59e-41` / `5.0e+36` /
`7.02e-43`）；在那个状态下**写也写不进去**（写一个属性会改动别的属性）—— 于是"拖一下
就变成 0 / 4.2e-45 / 0 / 0"。明度分量是 0 → `V' = V × 0 = 0` → 强调色全黑。
（`4.2039e-45` 是 float32 的**最小非规格化数**，只可能来自未初始化内存。）

**修法**（三道防线）：
1. **换属性名**（`preset_adjust_*`）—— 旧条目不再被读取，新属性拿到干净的声明默认值（根治）；
2. **读侧净化**：任何分量非有限 / 越界 / 非规格化，一律按该字段的中性值处理，
   渲染链永远拿不到会算出黑值的输入；
3. **入口一次性归一化**：打开主题页 / 拖滑杆 / 套用预设都会把已经坏掉的 16 个分量
   就地写回中性值 —— 老用户升级即自愈；另外滑杆的更新回调整段包了 `try/except`，
   任何意外只打印一条说明，**不会让拖动失效**。

色值集中写在 `theme.py` 的两个调色板字典里（马拉松是 `MARATHON`，旧名 `ACID`；死亡搁浅是
`STRANDING`），想微调直接改 hex 就行（主题里存的就是显示值，`/255` 直接换算）。
马拉松那两套用到的色（照着《失落星船：马拉松》实拍图取色）：

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| `lime` | `#D6F32B` | 主行动色：READY 按钮、警示文字、罗盘标记（**视口里被选中的几何**也用它） |
| `lime_dim` | `#9FB420` | 暗一档的黄绿（已修改标记） |
| `magenta` | `#E85BC8` | 任务横幅、货币数字、队伍标识（第三强调，少量点缀） |
| `magenta_dim` | `#A03E8B` | 暗一档的洋红（驱动器状态） |
| `cyan` | `#3FB6E0` | 副标题、次要标识（次强调） |
| `cyan_dim` | `#2A7E9E` | 暗一档的青蓝（有动画状态） |
| `crimson` | `#E0433A` | 危险 / 禁止（被覆盖状态） |
| `card` | `#C4C6C9` | 浅灰任务卡底色（浅灰卡预设的按钮底色） |

预设默认**只改按钮、状态色、时间线当前帧、视口里被选中的几何与视口底色**
（「马拉松 浅灰卡」这一套不改视口底色），并把**基面网格线与法线写回出厂默认值** ——
所以套用后**时间线的当前帧指示也会跟着强调色变**（4.x 上生效；5.x 里 Blender 已经把那些项
删掉了，面板上会自动少掉这一组）。
注意：**套用预设本身**写的是一整张表（含背景 / 文字 / 边框），这是预设的设计；
上面那四个滑杆**只**调其中的**强调色部分**（v2.15.0 起），两者不是一回事。

> **视口里被选中的线 / 点 / 面一律用鲜亮档**（`#D6F32B`），不跟界面控件一起用低饱和档：
> 界面降饱和是为了长时间工作耐看，而"哪些东西被选中"必须一眼看清 —— 上一版把两者一起
> 降饱和，结果就是"被选中的线饱和度太低看不清"。这一条有真机断言守着：4 条视口选中路径
> 的饱和度必须 ≥ 0.6，且**不许等于低饱和档** `#B9CE4E`；同时界面控件（普通按钮 / 分组框 /
> 列表行）必须仍是低饱和档，防止"一改全亮"。**未选中的边、线框、特征标记**（缝合线 / 锐边 /
> 折痕 / 倒角权重）与网格线 / 法线都不受影响。
>
> **颜色到顶之后靠线宽**：调色板里饱和度最高的黄绿就是这个 `#D6F32B`（实测 **0.823**，
> 全表最高，没有更亮的黄绿可换）。所以两套马拉松预设还把**编辑模式选中边的线宽**
> （`view_3d.edge_width`，实测三版 factory-startup 都是 `1`）写成 **2** —— 颜色之外
> 唯一还能提升可见性的手段。它是**尺寸项**（整数、不是颜色），所以「恢复全部」里
> 会有一步把它写回 `1`；想自己改：Blender 的 主题 → 3D 视图 里也能看到它。
> **未验证**：无头环境里看不到画面，这条的实际观感（线是否更清楚）没法自动断言，
> 只实测了"属性存在 + 可写 + 写入后读回一致"。

##### 「死亡搁浅」配色

冷色工业终端观感：**界面控件里蓝是主强调**，橙是点缀（含视口里被选中的几何）。

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 主强调（蓝） | `#4B7FA8` | 控件家族的选中行 / 选中态填充、节点选中（**界面控件仍然是蓝**） |
| 蓝深档 | `#2E4E68` | **需要在其上配浅色文字**的场合：滑块 / 数值框、工具栏图标、工具按钮 |
| 点缀橙 | `#D08A2E` | 面板活动标签，以及「已修改」状态（含其选中态的深一档 `#8A5A1E`） |
| **视口选中橙（高饱和）** | `#E0840B` | 3D 编辑模式里**被选中的几何**：活动元素 / 顶点 / 边 / 面（面是 50% 透明度填充） |
| 常态文字 | `#D6DADE` | 按钮 / 面板上的常态文字，灰白（不用纯白大面积铺陈） |
| 炭黑三级层次 | `#14171A` / `#1C2024` / `#262B30` | 视口与节点背景 / 面板底 / 浮起面板与活动标签（亮度递增，层级做得出来） |

`#E0840B` 是**由点缀橙按公式派生**的，不是新色相：色相沿用 `#D08A2E` 的 **34.1°**，
饱和度从 **0.779 推到 0.950**、明度从 **0.816 抬到 0.880**（抬明度是为了在冷炭黑视口
`#14171A` 上拉开亮度差）。推导：`C = V*S = 0.836`、`m = V-C = 0.044` → `(0.880, 0.519, 0.044)`。
用它的理由：视口里的线又细又压在深色背景上，`0.779` 的橙看着发灰，用户明确要"高饱和的橙色"。
真机断言守着：这 4 条路径的饱和度必须 **≥ 0.9**、必须**等于** `#E0840B`，且与视口背景
（`#14171A` / 面板底 `#1C2024`）的**亮度差 ≥ 0.3**。

**一处刻意的取舍（如实说明）**：选中态填充上用的是**深色文字 `#14171A`**，而不是浅灰白 ——
因为这个蓝在**饱和度降到 40%** 之后三通道互相靠拢、亮度会从 0.4663 升到约 0.586，浅色文字与
它的亮度差只剩约 0.27，达不到项目既有的「文字 / 底色亮度差 ≥ 0.3」；配深色文字则全程都够
（满饱和 0.399、降饱和后 0.519）。这也正是项目既有的"菜单高亮行 = 强调色底 + 近黑字"设计。

橙是点缀不是主色：整套预设里**所有暖色（红 / 橙 / 琥珀）只允许出现在 12 条白名单路径上**
（活动面板标题、已修改状态、关键帧选中、被覆盖、边缝合线、倒角权重，以及**视口里被选中的
几何那 4 条**），多出一条真机断言就会失败；色值一个都不散落在预设函数里，全部来自 `theme.py`
的 `STRANDING` 字典，改那一个字典就能整体换风格。

> 死亡搁浅的视口选中色**已经改过**（用户授权方案 a）：从原来偏冷的蓝 `#4B7FA8`
> （实测饱和度 **0.554**，在灰色模型上不如酸性黄绿醒目）换成**高饱和橙** `#E0840B`
> （饱和度 **0.950**），4 条视口选中路径全部换掉，界面控件的主强调仍然是蓝。

细节说明：

* 覆盖 70+ 项颜色，其中按钮/控件类包括：普通按钮、按钮描边与文字、按钮滑块、工具按钮、
  工具栏图标、单选/复选、开关、单选圈、数字框、数值滑块、文本输入框、菜单项与菜单背景、
  饼菜单、标签页、列表行、提示框、进度条、滚动条、分组框，以及它们各自的**选中态**
  （默认蓝的那一批）；状态色包括已修改 / 有动画 / 关键帧 / 驱动器 / 被覆盖
* **按版本自动过滤**：5.x 才有的 `user_interface.panel_*`、`wcol_state.error/warning/info/success`、
  `wcol_regular.outline_sel` 在 4.0 / 4.2 上不会出现，不需要你判断版本
* 主题颜色内部是 **8 位量化**存储的（写 0.5 读回 128/255 ≈ 0.50196），所以颜色会有极小偏差，这是 Blender 本身的存储方式
* RGB 类颜色项没有 alpha 通道，选择器里的 Alpha 会被忽略（面板上会提示）
* 「恢复默认」用的是 **4.0.2 与 5.2.2 上实测一致**的出厂值；5.x 专属项不记录默认值，
  免得把 5.x 的默认值套到 4.0 上
* 只改颜色，不动主题里的其它设置，也不影响你的主题预设文件

### 页面布局（N 面板 ▸ 工具 页）

把当前的工作区（Layout / Modeling / …）和每个工作区里的**区域划分**（哪个编辑器在哪、占多大）
存成一份带名字的快照，之后在新文件里一键还原。

| 按钮 | 做什么 |
| --- | --- |
| 名字 + `+` | 把当前布局存成这个名字（同名覆盖） |
| **使用** | 把选中的布局套到当前文件：缺的工作区自动补出来并改名，当前工作区里按位置把区域类型改回去；对不上的会如实报告，**不硬拆硬合区域**（那属于高风险操作） |
| **删除** | 从偏好设置里删掉这份布局 |
| **把当前窗口布局设为启动布局** | 把现在的工作区 / 窗口布局写进 Blender **启动文件**；**点之前会弹确认**（会覆盖 `startup.blend`）。新启动文件是**空场景 + 你的工作区布局**，当前场景不会被带进去 |

> 想"新建文件就是这个界面"，用**把当前窗口布局设为启动布局**（下一步有完整步骤）；
> 「使用」按钮管的是**当前文件**。布局存在插件偏好设置里（JSON），跟着偏好设置一起保存。

#### 启动布局怎么用（本版采用手动方案）

> 为什么是"手动方案"：本版 Blender 的脚本接口**删不掉工作区**、也**改不动活动工作区**，
> 这两步只能由你在界面里点一下 —— 详见第 2、3 步里的实测说明。插件不假装能替你做完。

1. **写启动布局**：N 面板 ▸ **工具** 页 ▸ **页面布局** ▸ 点
   **「把当前窗口布局设为启动布局」**（会先弹确认）。它**只写工作区布局**，
   新启动文件是**空场景**（不含当前场景），所以你现在的文件原封不动。
   点之前请先 <kbd>Ctrl</kbd>+<kbd>S</kbd> 保存当前文件（有未保存改动时它会拒绝执行）。
2. **清掉同名的「出厂 xxx」工作区（手动）**：中文界面下出厂启动文件里也有「布局 / 建模 / 着色 /
   UV 编辑」这些**同名工作区**，脚本删不掉它们，插件只能给出厂那份加「出厂 」前缀改名让位。
   实测两条路都不通：`bpy.ops.workspace.delete()` 会**返回成功却什么都没删**（另一种环境里抛
   `GPU API is not available in background mode` 后静默取消），而 `bpy.data.batch_remove()`
   虽然能删，删的若是窗口当前那个会让 Blender **退出时段错误崩溃**（实测 exit=11）—— 所以直接**禁用**。
   想清掉它们：**右键那个「出厂 xxx」工作区标签 ▸ 删除工作区**。
3. **指定"新开 Blender 默认显示哪套布局"（手动）**：新建一个空文件，**用鼠标点一下**你要的那套
   工作区标签，再走 **文件 ▸ 默认 ▸ 保存启动文件**。这一步必须手动 —— 实测脚本改不动当前工作区
   （给 `window.workspace` 赋值不生效），插件不会假装已经替你切过去了。

测试覆盖：JSON 往返（保存 / 列表 / 读取 / 删除 / 坏数据不崩）、空名字拒绝保存、
后台模式（没有窗口）`capture` 返回 None 且 `apply` 明确拒绝、启动布局算符带确认且 `confirm` 默认 False。

### 面板顺序（拖动排序）

N 面板 ▸ `红红子lab` ▸ 顶部切到 **工具** 页 ▸ **「面板顺序」** 面板（它自己固定在最后）：

按住每行左边的手柄上下拖，实时换位，松开确认、<kbd>Esc</kbd>（或右键）取消。
顺序存在插件偏好设置里，重启后仍然生效。**这个拖动是真的有效**，因为插件会按你的顺序
**重新注册自己的面板** —— 3D 视图侧栏的先后只看注册顺序（见下面的原理说明）。

> 要是按下去没跟手，就**移动鼠标**（会实时换位）再**点一下**确认 —— 面板按钮的算符
> 在某些情况下是鼠标**松开**时才启动的，那你那次 `按下 → 拖动 → 松开` 可能整个都发生在
> 拖动模式开始之前。状态栏会提示当前是「松开确认」还是「再点一下确认」。

下面还列出侧栏里现有的全部标签页（Item / Tool / View / 红红子lab / 其它插件……），
**仅供查看**，不能拖动排序 —— 原因见下。

> **为什么标签页不能排序（实测结论，不是偷懒）**
>
> 1. 想"按住标签页本身拖动"是不可能的：那一列标签由 Blender 的 C 代码绘制并处理鼠标，
>    Python 没有任何钩子可以拦截（社区里要排标签页只能另装 SIMPLE TABS 这类插件）。
> 2. 退一步"用插件帮它重新注册面板来改顺序"这条路**被我实测否决了**：
>    把 Blender 内置或其它插件的面板注销再注册，会直接让 **Blender 4.0.2 与 4.2.23
>    段错误崩溃**（进程退出码 11），5.x 上也会报 `already registered as a subclass 'Panel'`。
>    所以插件只重排**自己**的 5 个面板，绝不动别人的。

> 这些面板全部是**顶层面板**（没有用 `bl_parent_id`）：侧栏 N 面板不保证绘制子面板，
> Blender 自己的 N 面板脚本里一个子面板都没有，所以本插件一律用顶层面板，
> 并由测试静态守住这条（AST 检查类体里不许出现 `bl_parent_id`）。

原理与注意事项（都是实测/查源码得出的，不是猜的）：

* 顺序靠**重新注册面板**实现：3D 视图侧栏的先后由注册顺序决定（实测 Blender 源码
  `interface_panel.cc` 只按插入顺序给面板编号，`BKE_panel_new` 也不读面板类型的 order）。
  插件每次启用 / 拖动后都会按偏好设置重新注册**自己的**面板
* 同时也会写 `bl_order`（官方 RNA 说"数值小的排在前"，但侧栏不读它 —— 图像 / 序列 / 节点
  这些自己排序的编辑器才认），写上无害
* 「本插件的面板」这一项**有自动化断言覆盖**（算符注册与调用名一致、方向换算、
  `move_item` + `parse_order` 往返、写回偏好设置再读回、`bl_order` 与重排列表都按该顺序落实、
  重新注册成功且面板类一个没少、只碰本插件自己的 7 个面板）；
  **拖动手感本身仍需你在 Blender 里实际拖一下确认**
* **2.16.1 修的方向 bug**：拖动方向原来是反的 —— 鼠标往下拖，那一行会**往上**挪。
  原因是 Blender 的事件 / 区域坐标**以左下角为原点、Y 向上**（实测 4.5.14：3D 视图里画在
  最上面的 `HEADER` region.y=1417，`WINDOW` 只有 145），而代码直接把
  `event.mouse_region_y - 起始值` 当成"往下拖"的正位移用。现在统一走
  `panels.target_from_screen_drag()` 做换算，方向换算只在那一个地方，测试也盯着它

### ZML_LAB 一键更新（N 面板 ▸ 工具 页 ▸ 插件设置）

给 ZML_LAB 用的一段小工具：把新下载的 ZML_LAB 压缩包**剪切**进插件库，再用它**替换已安装的
ZML_LAB**，并且保证**插件设置与快捷键不变**。

| 项 | 说明 |
| --- | --- |
| 源目录 | 自动扫描 ZML_LAB 压缩包的目录，默认 `D:\日常软件\qq` |
| 库目录 | 压缩包要剪切过去的插件 zip 库，默认 `C:\build\Blender\4.0\4.0chajian`（不存在会自动创建） |
| 压缩包 | 源目录里**通过校验**的候选项（包内必须有 `ZML_LAB…/__init__.py`），按文件修改时间从新到旧；下拉里显示**短标签** `V1.07 - 1.7`（文件夹版本 + 代码版本），悬停提示里才有完整文件名与模块名 |
| **一键更新ZML_LAB** | 点一下弹确认（列出源包名 / 模块名 / 版本 / 目标库目录 / 会改名沿用旧模块 / 会移动源文件 / 会重新启用），确认后执行 |

> 2.21.1 起下拉的值是**纯 ASCII 标识符**（`zml_<哈希>`），不再是完整路径：旧版把路径当
> 枚举值，源目录含中文时会让 Blender 的枚举项缓存变成乱码字节，面板每帧抛
> `UnicodeDecodeError`（详见第四节「2.21.1：ZML_LAB 候选包命名的实测与断言」）。
> 找不到候选时报告会写清扫到了几个 zip、哪几个没通过校验、具体原因是什么。

点下去之后依次做：

1. **校验**候选包，并解析**要沿用的旧模块名**（见下面的"同族改名"）；库目录不存在就创建；
2. **备份**：已安装的旧 ZML_LAB 模块文件夹复制到
   `<addons>\_zml_backup\<模块名>-<时间戳>\`（库里被替换的旧压缩包也一起备份）；
3. **剪切**源压缩包到库目录（源目录里不再保留；库里存的是**原始包**，文件名与模块名都不改）；
4. **安装**：把包内顶层文件夹**改名为旧模块名**后写到临时目录，再
   `preferences.addon_install(overwrite=True)`（只替换同名模块），装完**立刻删掉**临时 zip；
5. **重新启用**：对**旧模块名**做 `addon_utils.disable` → `enable(default_set=True)`，
   让插件自己的快捷键重新注册，然后核对它确实处于启用状态；
6. **报告**：模块名、其中的代码版本、源 zip → 库路径、备份路径、是否重新启用。

#### 同族改名：为什么"模块名不变"才是快捷键不丢的关键

Blender 的插件偏好设置（ZML_LAB 自己的快捷键设置就在里面）是按**模块名 = 包内顶层文件夹名**
存的。而 ZML_LAB **每发一版都换顶层文件夹名**（`ZML_LAB_..._V100` → `ZML_LAB_..._V107`），
直接装进去 Blender 就把它当成另一个插件，原来那套设置与快捷键归不到新模块名下 ——
用户看到的就是"每次更新快捷键都没了"。

所以这里用**同族判定 + 改名安装**：

| 情况 | 处理 |
| --- | --- |
| 候选模块名**已在**已安装列表里 | 直接覆盖它（原样安装） |
| 候选与某个已安装模块**同族**（去掉尾部 `V<数字>` 后完全相同，例如 `..._V100` 与 `..._V107`） | 把新版顶层文件夹**改名为那个旧模块名**再装；同族里优先选**当前已启用**的那个，都没启用就选**版本序号最高**的 |
| 找不到同族 | **拒绝执行**，一个文件都不动（装下去会是新插件，设置与快捷键无法继承） |

> 结果就是：**模块名仍是旧的（例如 `..._V100`），里面换成了新代码（bl_info 版本是新版的）**。
> 插件列表里看起来还是同一个插件，设置与快捷键自然还是那一份。
> 确认弹窗会把「将把新版顶层文件夹 X 改名为 Y，以沿用同名插件，从而保留设置与快捷键」写清楚，
> 并如实说明"模块名仍是 X，里面装的是 Y 版的代码"。

任何一步失败都会**回滚备份**（源压缩包挪回原处、旧模块文件夹放回、被清掉的旧包从备份恢复、
临时 zip 删掉），并把**具体失败原因**写进报告 —— 不会谎报成功。

> 本功能**不写** `userpref.blend`（绝不调用 `wm.save_userpref`）、**不改** keymap、
> **不删**你的其它插件；对真实 addons 目录只做只读探测。

### 打开 Blender 自动切英文输入法（Windows，自动）

Windows 上默认输入法是中文时，Blender 一打开就是中文组字模式，空格 / 数字 / 方向键
会先被输入法吃掉。本版会在**打开 Blender（以及每次加载文件）之后约 0.3 秒**，把
**当前这块 Blender 窗口**的输入法转换状态切成**英文 / 半角**。

* 没有开关、没有面板、没有设置项：**默认总是执行**
* 只在 `sys.platform == 'win32'` 上做，其它平台**直接跳过**（不报错）
* 用 `ctypes` 调 `user32` / `imm32`：`GetForegroundWindow` → `ImmGetContext`
  → `ImmGetConversionStatus` → 清 `IME_CMODE_NATIVE`（`0x0001`）
  → `ImmSetConversionStatus` → `ImmReleaseContext`
* **只清 `IME_CMODE_NATIVE` 这一位**，其它位（全角 / 罗马字 / 软键盘等）原样保留
* 不合成任何按键（`SendInput` / `keybd_event` / `PostMessage` 一律不用）、不改注册表、
  不改系统输入法设置；只对**本窗口**发一次 IME 状态设置
* 前台窗口不是 Blender、窗口没有输入法上下文、任何一步失败 —— 都只打印一行说明并跳过，
  **绝不抛异常，绝不影响 Blender 启动**
* 触发时机：`bpy.app.handlers.load_post`（每次加载文件后）+ **一次性** `bpy.app.timers`
  延时 0.3 秒（等窗口就绪；回调只跑一次）。注册与注销在 `register()` / `unregister()` 里严格配对

> **已知限制（API 的边界，不是 bug）**：某些第三方输入法（以及部分远程桌面 / 输入法框架）
> 会忽略 IME 状态消息，这时输入法**不会**被切成英文，只能手动按 <kbd>Shift</kbd> 切换。

## 三、每个功能的具体行为（边界情况都处理了）

### 删除所有材质

* 材质槽**一起删掉**，不只是把材质设为空
* **材质数据块本身保留**，不会顺手删除其它物体还在用的材质
* 物体级材质槽（`link == 'OBJECT'`）和数据块级材质槽都会清
* 网格 / 曲线等所有带材质的数据类型都支持；对空物体、灯光、摄像机等不会报错

### 应用所有修改器

* **逐个应用**，保持修改器顺序
* 在视口里被**禁用**的修改器：先临时启用再应用，报告里会说明有几个是这种情况
* **多用户（共享）数据**：自动复制成单用户再应用，不影响共享同一份网格的其它物体
* **带形态键的网格**：Blender 不允许逐个应用，自动改用「转换为网格」一次性烘焙（会丢形态键，无法避免）
* **被隐藏的物体**：临时取消隐藏、做完还原原状态
* **不在当前视图层的物体**（所在集合被排除等）：跳过并在报告里点名
* **曲线/文字上的构建类修改器**：Blender 本身就拒绝应用（提示要转网格），插件会明确报错并**保持原样**，不会偷偷把曲线改成网格
* **链接自其它 .blend 的物体**：跳过并提示

### 删除所有修改器

* 直接丢弃，**不烘焙**，几何不变
* 纯数据操作，不依赖可见性

### 一键翻面

* 用 `bmesh.ops.reverse_faces` **原地**翻转所有面，**不进入编辑模式**
* **多用户网格先复制成单用户** —— 只有目标物体变，共用同一份网格的其它物体不受影响
* 非 Mesh 目标（Empty / 灯 / 曲线 / 摄像机……）**跳过并计数**，不报错、不中断其它物体
* 没有面的网格也会被跳过并单独计数
* 报告：`已翻面 N 个 / 跳过 M 个（非网格）（共 K 个面）`；多用户被复制时额外提示
* UV / 顶点组 / 材质槽不动；**自定义拆分法线与锐边数据会跟着面一起翻方向**，UV 的逐角顺序会重排（点到点的贴图位置不变）

### 检测是否有反面

* **只读**：不改网格、不改选择、不动可见性（源码级断言禁止写操作）
* 逐个物体 `print` 到系统控制台：物体名 + 判据 + 有符号体积或内指面比例
* 状态栏汇总：`检测 N 个：整体翻面 X 个 / 疑似 Y 个 / 正常 Z 个 / 跳过 W 个`
* 判据是**纯函数**（顶点坐标 + 面索引 → 结论），闭合网格用有符号体积（可靠），非闭合用「质心朝外」启发式（只报**疑似**）
* 判不了的情况（空网格 / 没有面 / 非 Mesh）跳过并计数，不算进四个数里的「正常」

### 一键查看面朝向

* 范围是**当前屏幕里所有 3D 视口**，不是只看鼠标所在那个
* 切换语义：只要有视口关着就全部打开；全部已打开才全部关闭（点一下就来回切）
* 切换后刷新界面区域；报告 `已打开 N 个视口的面朝向` / `已关闭 N 个视口的面朝向`
* 上下文里没有 3D 视口时只给 `当前上下文没有 3D 视口` 的提示并取消，不抛异常
* 用的是 Blender 自带叠加层开关，**不新增任何插件设置项**

### 灰度滤镜

* 范围是**当前文件里所有场景**（灰度是场景级设置，每个场景各记各的原 `look` 值）
* 切换语义：点一下开、再点一下关；关的时候**逐场景还原成开之前那一个 `look`**，不是无脑置 `None`
* 原状态记在场景自定义属性上（`hhz_grayscale_filter` + `hhz_grayscale_filter_previous_look`），
  跟着 `.blend` 保存、跟着撤销走；关掉时把这两个属性一起清掉，不留垃圾
* ⚠️ **会一起影响最终渲染输出** —— `look` 属于显示变换（display transform），不是视口专属开关；
  开/关两条报告都写明这一点与已还原
* 只碰 `view_settings.look` 一个值：不动色彩管理曲线、不动合成器、不动 `film_transparent`、不动选择
* 没有场景 / 拿不到 `view_settings` 时提示并返回 `CANCELLED`，**不抛异常**
* **不新增任何设置项 / 面板 / 依赖**

### 一键隐藏刀具（2.22.0）

* 刀具识别是**纯函数** `ops.detect_cutters(objs, references)`（不碰 `bpy`），所以无头环境能
  逐条穷举判据；布尔引用由 `ops.cutter_reference_map()` 只读扫出来（记下「谁引用它」）
* **判据 A** 只扫整个文件里的物体（不只是目标集合）—— 刀具被别的集合里的主体引用时也能认出来
* **判据 B** 认两种线框写法：`display_type == 'WIRE'` 与 `show_wire == True`
* **判据 C** 只在 A / B 都没命中时使用，报告里固定加一句「其中 Z 个仅按名字推断，不是确定结论」
* **排除并计数**：非 Mesh / Curve（Empty、灯、摄像机……）计入「跳过非网格」；
  已经隐藏的刀具计入「已在隐藏集合」，**不会重复 hide，也不谎报成隐藏成功**
* 只调 `hide_set(True)`；单个物体失败只计入「失败 F 个」并打到控制台，不中断其它物体
* 报告里带「恢复：Alt+H」；一个都没找到时返回 `CANCELLED`
* `target_mode` 三档：`PREF`（默认，饼项不传参数时走这一档 = 既有目标机制）/ `SELECTED` / `COLLECTION`
  （枚举 identifier 全是纯 ASCII）

* **图标存在性**：`HIDE_ON` 由既有的 `test_icons` 用例逐个内省
  （`UILayout.operator` 的 `icon` 枚举）核对，4.0.2 与 5.2.2 都通过。

**未验证（如实标注）**：无头环境画不出真的饼菜单，所以「肉眼看到右上角那个按钮长什么样」
**没有做无头验证** —— 能验证到的是「加进 pie 的顺序、算符 idname、图标名合法、饼项没带参数」。
另外饼菜单的实际点击也没有自动化覆盖（算符本身有运行期断言）。

### 2.22.0：一键隐藏刀具的实测与断言

**需求原话**：「再加一个功能一键隐藏组里面的所有刀具（刀具是一个物体去布尔切割别的物体的后变成的线框）」。
按这句话实现，**不靠名字猜**：判据 A > B > C 三条优先级，见第二节「一键隐藏组里的所有刀具」。

**新增的三块纯函数（都不碰 `bpy`，所以无头环境能逐例穷举）**：

| 函数 | 作用 |
| --- | --- |
| `ops.cutter_reference_map(holders)` | 只读扫 `type == 'BOOLEAN'` 的修改器 → `{被引用物体名: ["谁 的 哪个修改器", ...]}`（`OBJECT` 型取 `mod.object`，`COLLECTION` 型取 `mod.collection.objects`） |
| `ops.detect_cutters(objs, references)` | 按 A > B > C 判定 → `(刀具列表, 统计)`；统计里分开 `by_modifier` / `by_wire_name` / `by_name_only` / `skipped_non_mesh` / `skipped_hidden` |
| `ops.describe_cutters_report(stats, failed)` | 统计 → 一行中文报告 |

**逐例实测（4.0.2 与 5.2.2 都是同一套断言、同一份结果）**：

| 用例 | 期望 | 实测 |
| --- | --- | --- |
| A 被 `operand_type='OBJECT'` 的布尔修改器引用 | 识别成刀具，归 A | ✔ `reason == modifier`，并记下「主体 的 布尔切割」 |
| A 集合型布尔引用集合里的两个物体 | 两个都识别，归 A | ✔ 两个都进列表，计数 `by_modifier == 2`，描述带「（集合布尔）」 |
| B 线框 + 名字含 `cutter`（无布尔引用） | 识别成刀具，归 B | ✔ `reason == wire_name` |
| B 的另一种线框写法 `show_wire == True` | 同样归 B | ✔ |
| 普通线框物体（名字不含关键词、无布尔引用） | **不得**识别 | ✔ 列表为空，也不进 `skipped_non_mesh` |
| C 实体物体、名字含 `cutter`（非线框、无布尔引用） | 只在兜底 C 出现 | ✔ `reason == name_only`，报告带「仅按名字推断，不是确定结论」 |
| 非网格（Empty / Light，名字还像刀具） | 跳过计数 | ✔ `skipped_non_mesh == 2`，不被隐藏 |
| Curve（线框显示） | 仍是合法刀具类型 | ✔ 识别 |
| 已经隐藏的刀具 | 跳过并计数，不谎报成功 | ✔ 进 `skipped_hidden`，不再进待隐藏列表 |
| 三条判据同时命中 | 归 A（最可靠） | ✔ `reason == modifier`，且不重复计入 B / C |
| 只有 `SUBSURF` 等非布尔修改器 | 不算引用 | ✔ 引用表为空、不识别 |

**算符行为实测（真机跑，逐物体 `hide_get()` 核对）**：

* 选中模式：造「主体 + A/B/C 三个刀具 + 普通实体块 + 普通线框 + Light + Empty」共 8 个物体，
  跑一次 → 三个刀具 `hide_get() == True`，**其余 5 个全部 `False`（非刀具一个都没被隐藏）**，
  控制台实测报告：`已隐藏 3 个刀具：被布尔修改器引用 1 个、线框+命名 1 个、仅按名字 1 个；跳过非网格 2 个、已在隐藏集合 0 个、失败 0 个；其中 1 个仅按名字推断，不是确定结论；恢复：Alt+H`
* 集合模式：把刀具放进 `HHCutters父组`，其中一个放子集合，主体与另一个线框刀具留在集合外 →
  跑一次只隐藏**父组 + 子集合**里的 2 个，集合外的主体与线框刀具都没有被隐藏
  （报告：`已隐藏 2 个刀具：被布尔修改器引用 1 个、线框+命名 1 个、仅按名字 0 个；…`）
* **幂等**：连跑两次隐藏结果逐物体一致，第二次 `hidden == 0` 且如实返回 `CANCELLED`；
  复位后再跑，识别结果与隐藏集合和第一次逐条相同
* **找不到刀具**：`CANCELLED`，一个物体都没被隐藏，汇总全 0；提示里写明「依据：布尔修改器引用 / 线框+命名」
* **不做多余动作**：显示类型仍是线框、布尔修改器还挂在主体上且指向同一个刀具、顶点数不变；
  源码级断言算符里没有 `display_type` 赋值 / 没有 `objects.remove` / 没有 `select_set` / 没有 `modifiers.*` 写操作
* **可撤销**：`bl_options` 含 `REGISTER` 与 `UNDO`（运行时 + 源码级双查）
* **枚举 identifier 纯 ASCII**：2.22.1 起 `target_mode` 的三项是 `PREF` / `SELECTED` / `COLLECTION`，
  逐个匹配 `^[A-Za-z0-9_]+$`，顺序固定、默认值就是 `PREF`
* **UI / 面板**：建模页主面板里两个按钮（同一个算符两种显式目标），紧跟翻面那一组、同一个 column，
  **没有新增面板**；`draw` 里那段包在 `try/except` 里；面板文案没有中点号 U+00B7；
  **饼菜单右上那一格就是它**（2.22.1 起，饼项不传参数 → 回落成按偏好设置，见下一节）
* **收尾清理**：测试建的物体与集合都删掉，不污染后面的用例

> **未验证（如实标注）**：无头环境画不出真实 N 面板，所以「按钮在侧栏里的实际排布与观感」
> **只做了源码级 + 结构级断言**（两个按钮确实在 `HHZ_PT_main` 里、`target_mode` 确实被赋值），
> 真实 GUI 里点一下的手感需要你在 Blender 里看一眼。

### 2.21.1：ZML_LAB 候选包命名的实测与断言

**用户报的两个症状**（同一根因）：①「压缩包」下拉显示乱码；② 点「一键更新ZML_LAB」报
「找不到要更新的 ZML_LAB 压缩包：」（冒号后空白）。Blender 控制台里每帧都在打印：

```text
File "...\addons\redkolab\ui.py", line 549, in draw
    operation.candidate = preferences.zml_candidate
UnicodeDecodeError: 'utf-8' codec can't decode byte 0x01 in position 0: invalid start byte
```

**根因（本机实测，不是推测）**：旧版把**完整路径**当 `zml_candidate` 枚举的 identifier。
源目录是 `D:\日常软件\qq`，路径含中文 —— Blender 的**动态枚举项缓存**在 identifier
不是纯 ASCII 时会退化成一串乱码字节。实测（`blender -b`，隔离沙箱，装 2.21.0 的包）：

| 场景 | `preferences.zml_candidate` 读回 | 设值 |
| --- | --- | --- |
| 源目录 `%TEMP%\...\source`（纯 ASCII） | 正常路径 | `SET-OK` |
| 源目录 `%TEMP%\日常软件\qq`（含中文） | 4.0.2：`''` / 5.2.2：**`UnicodeDecodeError: 'utf-8' codec can't decode byte 0x80 in position 0`** | `TypeError: enum "..." not found in ('p\ufffd\ufffd\ufffd\x08\x02', ...)`（枚举项列表本身已是乱码字节） |

也就是说：**只要 identifier 里出现非 ASCII，Blender 交给 Python 的枚举项就已经坏了** ——
读值是乱码字节（有时恰好是 `0x01` 开头 → 用户看到的那个 `UnicodeDecodeError`），
写值直接查不到项。`draw()` 里那一行每帧读它，于是面板的下拉和按钮一起废掉；
按钮拿不到候选值，就只能报「找不到……：」加一个空串。

顺带修掉一个**同族**问题（不是崩溃原因，但同样是缺陷）：`zipfile` 只在成员名打了 UTF-8
标志（`flag_bits & 0x800`）时按 UTF-8 解码，**没打标志一律按 CP437 解**。中文 Windows 上
打的包常常是「GBK 字节 + 不打标志」，于是 `ZML_LAB_椎木兰_V200` 读回来是
`ZML_LAB_╫╡─╫╘╜╙_V200` 这种乱码 —— 而它**会冒充合法模块名**被后面的同族改名 / 确认文案
继续用下去。真实包 `ZML_LAB_Ultimate_Max_V1.07.zip` 的成员名是纯 ASCII（`flag_bits=0x0000`），
所以不受影响；受影响的是中文名成员名的包。

**2.21.1 的三层修复**：

1. **名字解码要健壮**：新增纯函数 `ops.zml_decode_name(name, utf8_flag)` —— 打了 UTF-8 标志
   就原样用；没打标志时按「CP437 编回原始字节 → `utf-8` → `gbk` → 原样」试探解码，
   任何异常都吞掉并回退，**绝不抛异常**；解出控制字符的名字不算合法模块名。
2. **标识符必须纯 ASCII**：`zml_candidate` 的 identifier 改成 `zml_<12 位哈希>`
   （`ops.zml_candidate_id`，只由「归一化模块名 + 文件名」算出，跟目录无关、可复现）；
   人类可读的部分放进 **`label`，而且是短标签**（`V1.07 - 1.7`，最长 32 字，
   不用完整路径 —— 长中文标签在弹出框里会被 Blender 按像素宽度截断成乱码，见
   第七节「颜色项下拉出现乱码」那次的教训）；`items` 回调**整段 try / except**，
   出错只返回一项 `（扫描失败，详见控制台）` 并把 traceback 打到控制台，
   **绝不让 `draw()` 抛异常**。此外这个枚举带 `SKIP_SAVE`（候选列表本来就是动态的，
   存下来只会变成指向旧条目的坏值），面板 `draw()` 里还加了一层护栏 + 旧坏值自愈
   `ui.heal_zml_candidate`，所以**已经存坏的旧偏好设置也能直接用**。
3. **算符取值要稳**：算符从 `preferences.zml_candidate`（现在一定是 ASCII id）**反查**
   扫描结果表里的真实路径（不依赖名字；旧版存下的完整路径也认），找不到时报告写明
   「在 `<源目录>` 找到 N 个 zip，其中 M 个像 ZML_LAB 但校验未通过（逐条原因：模块名
   解码失败 / 含控制字符 / 缺 `<模块名>/__init__.py`）」，**不再出现空冒号**。

**新增断言（78 / 78 / 59 条）**，覆盖：CP437 中文成员名样本解码后可读（GBK 与 UTF-8
两种原始字节）、垃圾样本（`\x01` / NUL 成员名）下 `items` 回调不抛异常且算符给出明确错误、
**遍历下拉的所有 identifier 逐个匹配 `^[A-Za-z0-9_]+$` 且是纯 ASCII**、label 无控制字符 /
无中点号、**Blender 层面读 `preferences.zml_candidate` 不抛异常且每个 identifier 都能设进去
再读回（含中文源目录）**、真实包 `ZML_LAB_Ultimate_Max_V1.07.zip` 能解出模块名
`ZML_LAB_Ultimate_Max_V107` 与版本 `1.7`（短标签 `V1.07 - 1.7`）。

**未验证（如实标注）**：无头环境画不出面板，所以「GUI 里下拉真的显示成
`V1.07 - 1.7`、点按钮真的弹出确认框」只能在 GUI 里看 —— 这一版能自动验证到的是
「枚举读值 / 设值都正常 + 标签内容就是那串短文本」，**实际观感待用户实测**。

## 六、自动发布与归档

打一个 tag，就会自动完成「打包 → 自检 → 多版本真机测试 → 发布 → 归档」：

```powershell
powershell -ExecutionPolicy Bypass -File tools\release.ps1 -Bump patch
```

这条命令依次做：检查工作区干净 → 升版本号（`bl_info` 与 `blender_manifest.toml` 一起改，永远同步）
→ 版本一致性检查 → 打包 → 安装包结构自检 → **复制进本地插件 zip 库并替换旧版本**
→ 提交 → 打 `v<版本>` tag（如 `v2.12.1`）→ 推送（带重试）。
任何一步不过就直接中止，不会把坏包推上去。加 `-DryRun` 可以只看检查结果不推送。

**本地插件 zip 库**默认是 `C:\build\Blender\4.0\4.0chajian`（真实物理路径；`D:\build\Blender`
是指向 `C:\build\Blender` 的 Junction 目录联接，两种写法是**同一个目录**，不要再把它们当成两处）：
每次发版会把新的 `redkolab-<版本>.zip` 复制进去，并删掉里面的旧版本
（只删该目录下匹配 `redkolab-*.zip` 的文件，别的插件包与文件夹一律不碰）。
目录不存在时只会创建这一个目录，其它目录一律不自动创建、不自动删除。

**已安装副本**默认是 `%APPDATA%\Blender Foundation\Blender\4.0\scripts\addons`：每次发版会把
`redkolab\` 整个替换成新版本的内容，这样 Blender 下次启动加载的就是最新的
（**装完记得重启 Blender**，或停用再启用插件）。想换目录用 `-DeployTo` / `-InstallTo`，
不想动本地用 `-NoDeploy` / `-NoInstall` 跳过，想留历史 zip 用 `-KeepOld`：

```powershell
powershell -ExecutionPolicy Bypass -File tools\deploy_local.ps1 -Target "C:\其它\插件库" -InstallTo "D:\其它\addons"
```

推送后 [.github/workflows/release.yml](.github/workflows/release.yml) 自动执行：

| 阶段 | 内容 |
| --- | --- |
| 打包自检 | tag 与源码版本一致性、打包、结构自检（布局 / 元数据 / 属性写法 / 上下文覆盖）、生成 SHA256SUMS.txt |
| 真机测试 | 下载 Blender **4.0.2（下限版本）+ 最新稳定版**（首次下载后走缓存），在隔离的配置目录里真装真跑 1400+ 项断言；最新稳定版上再额外走一遍扩展页安装入口 |
| 发布归档 | 建立 Release，把 `redkolab-<版本>.zip` 与 `SHA256SUMS.txt` 作为附件永久归档 |

> CI 的矩阵与本地矩阵一致，只有这三条：**4.0.2 auto / 最新稳定版 auto / 最新稳定版 extensions**。
> 4.0.2 用的是官方下载地址 `https://download.blender.org/release/Blender4.0/blender-4.0.2-linux-x64.tar.xz`
> （实测 HTTP 200、277588768 字节），不依赖任何第三方 action。
> **CI 改动只有在下一次打 tag 时才会真正执行** —— 本次只是改了工作流文件，未触发过 CI 运行，属**未验证**状态。

**任何一步失败都不会发布** —— 不会出现版本号对不上的包或装不上的包被归档。

只想构建和测试、不发版：仓库页 ▸ Actions ▸ Release ▸ Run workflow（手动触发不发 Release）。

## 七、已知限制

* 编辑模式下按钮是灰的（Blender 不允许在编辑模式改动材质/修改器数据），面板会提示切回物体模式
* 饼菜单的「按下新按键…」捕获需要真实窗口，无法在无头环境自动化测试，其余功能都有自动化覆盖
* **非闭合网格的「有没有反面」只能是「疑似」**：开口壳没有严格的「内 / 外」，用的是「质心朝外」
  启发式 —— 凹壳（L 形、甜甜圈、U 形）里本来就可能有过半的面「朝着质心」，会**误报**；
  平面 / 单层结构没有内外之分。只有闭合网格的有符号体积才是可靠结论
* **一键翻面翻转的是面朝向**：UV 是「逐面的每个角」存的，翻转后逐角顺序会跟着重排
  （点到点的贴图位置不变）；**自定义拆分法线与锐边数据的方向也会跟着翻过去**。
  造型上依赖这些数据时请先备份文件，翻完觉得不对就 <kbd>Ctrl</kbd>+<kbd>Z</kbd>
* **一键查看面朝向只切显示开关**：自动化只能验证开关值被正确改写，真实界面里是否真的渲染成
  蓝/红（以及颜色是否被你的主题/显卡设置影响）需要你在 GUI 里看一眼 —— 如实标注为未验证
* **自动切英文输入法只在 Windows 上生效**，而且**真实输入法是否真的被切成英文只能在 GUI 里看**：
  无头环境只能验证纯函数的逐位行为、平台守卫、handler 的注册 / 去重 / 注销配对，以及
  「源码里没有键鼠注入」这类约定 —— 这一条如实标注为**未做无头验证**。
  另外**某些第三方输入法会忽略 IME 状态消息**（API 限制），那时输入法不会切过去，只能手动按 <kbd>Shift</kbd>
* 曲线的构建类修改器无法应用（Blender 的限制，见上文）
* 「应用所有修改器」遇到形态键会丢失形态键（转换烘焙的固有代价）
* 主题颜色按 8 位量化存储，写入值读回会有约 1/255 的偏差（Blender 本身的存储方式）
* RGB 类主题颜色项没有 alpha 通道，颜色选择器里的 Alpha 会被忽略
* 主题改动立即生效，但想重启后保留需要点「保存到偏好设置」（或正常退出 Blender 让偏好自动保存）
* 5.x 独有的 `user_interface.panel_*` 颜色项在 4.0 / 4.2 上会自动隐藏（不是 bug）
* 面板顺序的**拖动手感**无法在无头环境自动化验证（重新注册的机制、方向换算、
  持久化都有断言覆盖）；2.16.1 修掉了"往下拖却往上挪"的方向 bug，但**真模态仍然只能手测**
* **侧栏的标签页不能排序**：一是标签栏由 Blender 的 C 代码处理、Python 没有钩子；
  二是"帮它重新注册面板"这条路实测会让 Blender 4.0 / 4.2 段错误崩溃。
  「面板顺序」面板里只列出标签页供查看
* 默认快捷键 <kbd>Ctrl</kbd>+<kbd>E</kbd> 在**编辑模式**下会与 Blender 的「边」菜单冲突（Blender 优先），
  所以饼菜单在编辑模式下不弹出；偏好设置里可以随时换成别的键
* **侧栏的标签页本身没法用鼠标拖动排序**：那部分是 Blender 的 C 代码绘制并处理鼠标的，
  Python 没有钩子（社区里排标签页也要另装 SIMPLE TABS 之类插件）；而用重新注册面板的方式
  去改别的插件的顺序，实测会让 Blender 4.0 / 4.2 崩溃，所以本插件不做这件事
* **颜色项下拉可能出现乱码**（只有那个弹出条目框，面板其它中文正常）—— 本版改成两级短选择
  从**结构上消除长列表**，见下面一小节
* 两级选择器只是"把长列表拆成两个短列表"的**结构性**改动：弹出框绘制层的实际观感
  （还有没有截断/乱码）**无头环境测不了**，需要你在 GUI 里看一眼 —— 这一条如实标注为未验证
* 「自定义预设」是**覆盖式**的（同名保存即覆盖）；界面上没有单独的"删除自定义预设"按钮
  （它和「自定义配色」共用同一份数据，但不出现在那个下拉里，避免看到一个自己没起过的名字）
* **2.15.0 的升级事故已修**（见上文「2.15.0 事故」）：2.15.1 换掉了那四个属性名，
  旧 userpref 里的四条标量条目会一直留着不再被读取（无害，只占几十字节；
  本插件没有"清理旧偏好键"这种破坏性动作）。升级后那四个滑杆从**原样**开始，
  之前调过的值需要重新调一次。
* **上一版为什么没抓到**（测试面的教训，已补断言）：2.15.0 的用例只在**全新偏好**上跑 ——
  "全新安装 → 写到槽位里 → 读回来"这条链是干净的，从没构造过
  ①**旧版本升级**（旧 userpref + 新属性类型）②**非法槽位**（空 / 拼错 / 已删除的预设名）
  ③**垃圾分量**（未初始化内存那种）
  这三类状态。2.15.1 新增的 `test_adjust_preferences_hygiene` 专门覆盖这三类：
  全新安装 16 个分量**逐个**核对中性默认、只有旧标量的偏好对象必须走中性分支、
  NaN / Inf / 越界 / `4.2039e-45` 四种垃圾分量下渲染结果必须**逐项等于预设底表**（不许变黑）、
  "拖一次只改当前槽位那一个分量（其余 15 个逐分量不变）"、以及滑杆回调在极端 / NaN 输入下
  **不抛异常**。这条用例被排在整套断言的最前面，跑在**任何**用例动过这四个值之前。
* 「自定义预设」的**强调色集合**是"三套内置预设共同认作强调色的那批槽位"（它的色表是一份快照，
  没有工厂可以在写的时候登记路径）。取交集而不是并集，所以**只会少几条、不会把背景色算进来**：
  只有某一套预设才当强调色用的路径（如死亡搁浅的「节点编辑器选中节点」）落在交集之外，
  拖滑杆时它不会跟着变色 —— 想要它跟着变，请在那套内置预设上调，或直接用「逐项微调」单独改它
* 四个调整值的**用户可见语义**（只调强调色、每个预设各存一份）在无头测试里是逐项断言的，
  但"拖动手感"本身仍需在 GUI 里体验
* 许可证：GPL-3.0-or-later（Blender 插件的通行许可）

### 故障排查：颜色项下拉出现乱码怎么办

**现象**：N 面板 ▸ 主题 页 ▸ 进阶 ▸「逐项微调」里的**颜色项下拉**，弹出的条目显示成
`¤C` / `°ðC` 这类乱码，而同一个面板的其它中文（「逐项微调」「颜色项」「自定义配色」）正常，
鼠标悬停提示气泡里的路径（`user_interface.wco…`）也正常。

**结论：不是数据坏了**（包里的源码是合法 UTF-8、无 BOM，按 UTF-8 解码「底色」这类中文完全正常），
而是那个**弹出条目框的绘制层**问题：条目一多，列宽有限，Blender 会把放不下的条目标签
**按像素宽度从中间截断**（`interface_widgets.cc` 里的 `text_clip_middle` / `text_clip_middle_ex`），
中文字被切在半个字上时，落单的多字节会被画成乱码 —— 那个函数里就留着
`TODO: proper handling of non UTF8 strings` 的注释，说明 Blender 自己也承认这条路径对非 ASCII 不完善。

**2.14.0 的做法：两级短选择，从结构上避免"长列表被截断"** ——

1. **第一级**选**分组**（短词，本版本最多 21 组，最长 6 个字）；
2. **第二级**只列这一组里的颜色项（每组 4～24 项，标签不再重复拼分组名，最长的第二级列表
   也从原来的 200+ 项降到二十几项）。

也就是说：**一次要画的长列表没有了**，弹出框不需要为了列宽去截断那么多条目。
「恢复本项 / 本组 / 全部」、调色盘、「应用颜色」、明文「当前值」这些链路一个都没动
（第一级的分组就是「恢复本组」用的那个分组）。

> **这是"结构性消除长列表"，不是"乱码已修复"**：那个弹出框的**绘制层**在无头环境里测不了，
> 所以本版只断言了"结构上不会再有 200+ 项的长列表""每条可用路径都能被两级选到"
> （可达集合 == 可用集合），**实际观感仍需你在 GUI 里看一眼**。
> 如果换成两级之后仍然偶发乱码，那说明根源在你的界面字体或 Blender 的绘制层，可继续试下面两步：

1. **打开「简洁模式」**（主题页里的开关）：每一组里的项再减少一批，弹出框更短；
2. **清空自定义界面字体**：`编辑 ▸ 偏好设置 ▸ 界面 ▸ 界面字体` 把文件路径清掉（改用 Blender 自带字体）再看一次 ——
   自定义字体缺字或字宽异常时，这类截断问题更容易暴露。

另外两条不受影响的路子：

* 改某个**家族**的整组颜色，用「**控件颜色分开设置**」（家族 + 7 个部位：底色 / 图标与文字 / 边框 /
  选中底色 / 选中文字 / 选中边框 / 高亮条，中文显示正常）；
* 想按路径逐个核对，看鼠标悬停的提示气泡，或用「全局按钮配色」「自定义配色」这两块。
