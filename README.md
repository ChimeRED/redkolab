# 红红子lab (REDKO_LAB)

[![Release](https://github.com/ChimeRED/redkolab/actions/workflows/release.yml/badge.svg)](https://github.com/ChimeRED/redkolab/actions/workflows/release.yml)
[![最新版本](https://img.shields.io/github/v/release/ChimeRED/redkolab)](https://github.com/ChimeRED/redkolab/releases/latest)

一个 **Blender 4.0 ~ 最新版通用的单文件插件**，把三个高频操作变成一次点击：

| 功能 | 说明 |
| --- | --- |
| 🔧 删除所有材质 | 一键清空选中物体的全部材质槽（材质数据块本身保留在文件里） |
| ✅ 应用所有修改器 | 一键把所有修改器烘焙进网格 |
| 🗑 删除所有修改器 | 一键丢弃全部修改器（不烘焙） |
| 🪜 一键楼梯 | 体块整成 0.3 宽 × 0.2 高（长度不变）+ 相对偏移阵列；移动鼠标换方向、滚轮改节数、左键确认 |
| 🎨 主题颜色 | 底色 / 图标与文字 / 边框 **分开设置**（每项自带小调色盘 + 自动配文字色 + 对比度检查）+ 调色盘与十六进制自定义色 + 时间线当前帧 + 3 套配色预设（马拉松 建模 低干扰 / 马拉松 浅灰卡 / 死亡搁浅）+ 第 4 个可存的「自定义预设」+ **色相 / 饱和度 / 明度 / 选中几何饱和度** 四个调整滑杆（**只调强调色，且每个预设各自独立**）+ 自定义配色 |
| 🔤 字体设置 | 界面缩放、DPI、自定义界面字体 / 等宽字体、抗锯齿、hinting、线条宽度（写进 Blender 偏好设置） |
| 🖥 页面布局 | 把工作区 + 区域划分存成快照，在新文件里一键还原；也能直接存成启动布局 |
| ↕ 面板顺序 | 拖动调整**本插件自己的面板**在 N 面板里的上下顺序（并列出侧栏现有标签页） |

三种呼出方式：

1. **饼菜单** —— 默认快捷键 <kbd>Ctrl</kbd>+<kbd>E</kbd>（可改成任意按键）—— **上面 1~4 四个功能**
2. **N 面板** —— 3D 视图 ▸ 侧栏（<kbd>N</kbd>）▸ `红红子lab` 标签页 —— 里面最上面一排是
   **「建模 | 工具 | 主题」** 三个分页按钮（样式参考插件库里 ZML_LAB）：
   **建模** = 三个一键功能；**工具** = 饼菜单与快捷键 / 插件设置 / 面板顺序；
   **主题** = 主题颜色（控件配色 + 配色预设 + 字体设置）
3. 搜索菜单（<kbd>F3</kbd>）里直接搜「红红子lab」或「REDKO」

> 「插件设置」原来在饼菜单里，已按需求挪到 N 面板；主题颜色也只放 N 面板。
> 这两条都有自动化测试盯着（直接解析安装后的 `ui.py` 断言饼菜单就是那四个功能入口），改坏会立刻失败。

插件列表里显示的名字是 **红红子lab (REDKO_LAB)**，中英文都能搜到。

## 一、安装：一个 zip 通吃 4.0 ~ 最新版

只有一份安装包，从 **[Releases 页面](https://github.com/ChimeRED/redkolab/releases/latest)** 下载
`redkolab-<版本>.zip` —— 每个版本一条永久归档，附件里还有 `SHA256SUMS.txt` 可校验。

本地自己打也可以：`python tools/build_zips.py`，产物在 `dist/`（`dist/` 不入库，安装包一律由 Release 归档）。

| 你的 Blender | 怎么装 |
| --- | --- |
| **4.2 及以上**（4.2 / 4.3 / 4.4 / 4.5 / 5.x） | 偏好设置 ▸ **扩展 / Get Extensions** ▸ 右上角下拉 ▸ **Install from Disk**，选这个 zip；或者**直接把 zip 拖进 Blender 窗口** |
| **4.0 / 4.1** | 偏好设置 ▸ **插件 / Add-ons** ▸ 安装… ▸ **Install from Disk** |

> 同一个包在 4.2+ 的**插件页**也能装（会按传统插件方式加载，功能完全一样），
> 所以无论你习惯点哪个安装按钮都不会翻车。

装完在列表里勾选启用即可。**手动安装**：把压缩包里的 `redkolab/` 整个文件夹拷到

```
<Blender 配置目录>/scripts/addons/
```

Windows 一般是 `%APPDATA%\Blender Foundation\Blender\<版本>\scripts\addons\`。

### 为什么一个包能通吃

包里的结构只有一种，源码只有一份：

```
redkolab/
    __init__.py            <- 同时带 bl_info（传统插件元数据）
    blender_manifest.toml  <- 扩展清单（4.2+ 读这个）
    compat.py
    ops.py
    ui.py
```

4.2+ 的扩展安装器既能读根目录的清单、也能读单层目录里的清单；而 4.0/4.1 的传统安装器
只认「和模块同名的顶层目录」。把代码和清单一起放进 `redkolab/`，两种安装器就都满足了。

这是实测比出来的，不是猜的：

| 包内布局 | 4.0/4.1 插件页 | 4.2+ 插件页 | 4.2+ 扩展页 |
| --- | --- | --- | --- |
| 代码放根目录 + 目录副本 | 可以 | **报错** | 可以 |
| **只有目录（本包采用）** | 可以 | 可以 | 可以 |

> 根目录带 `__init__.py` 的包会被 4.2+ 的插件页安装直接拒绝
> （`ZIP packaged incorrectly; __init__.py should be in a directory`），
> 这是 Blender 对扩展包的固有行为，不是本插件的问题。

## 二、使用

**前提**：物体模式 + 选中至少一个物体。没有选中任何物体时，会自动作用在**活动物体**上。

### 饼菜单

在 3D 视图里按 <kbd>Ctrl</kbd>+<kbd>E</kbd>，四个方向：

```
            上：一键楼梯
左：删除所有材质            右：应用所有修改器
            下：删除所有修改器
```

（原来的「插件设置」入口已挪到 N 面板的「插件设置」面板。）

> 注意：<kbd>Ctrl</kbd>+<kbd>E</kbd> 在**编辑模式**下是 Blender 自己的「边」菜单，
> 模式专用键位的优先级更高，所以饼菜单在编辑模式下不会弹出（物体模式下正常）。
> 想在任何模式都能用，可以在插件偏好设置里换一个不冲突的键。

### 一键楼梯（模态）

选中一个**体块**（立方体之类），点「建模」页的 **一键楼梯** 或按饼菜单的 **一键楼梯**，
然后：

| 操作 | 效果 |
| --- | --- |
| 移动鼠标 | 按方向换阵列方向：**右** `(1,0,-1)` / **左** `(-1,0,-1)` / **上** `(0,1,-1)` / **下** `(0,-1,-1)`；`z` 恒为 `-1`（楼梯往下走），**体块朝向也跟着换** |
| 滚轮上 / 下 | 楼梯节数（阵列数量）`+1` / `-1`，范围 1~500 |
| 左键 | 确认（保留体块尺寸与阵列） |
| 右键 / <kbd>Esc</kbd> | 取消，体块尺寸恢复原样、阵列删掉 |

尺寸与阵列约定：

* **高度（Z）恒为 0.2 m**；
* **沿阵列方向的那条水平边 = 0.3 m**，另一条水平边**保持选中前的尺寸**：
  * 左右方向 → **X = 0.3**、`Y` 不变
  * 上下方向 → **Y = 0.3**、`X` 不变
* 用的是 **Array 修改器 + 相对偏移**（`use_relative_offset`）—— 相对偏移是「系数 × 该轴尺寸」，
  所以系数 `(1, 0, -1)` 每级往 `+X` 挪 0.3 m、系数 `(0, 1, -1)` 每级往 `+Y` 挪 0.3 m，
  两种都是往下 0.2 m —— **改尺寸不用改系数**，方向一换体块会按新轴向重新整型
  （另一条水平轴回到你选中它时的尺寸）；
* 阵列是**活的修改器**（名字叫「红红子lab 楼梯」），随时能改节数/系数，
  想烘成实体就点「应用所有修改器」；重复点一键楼梯会**复用**同一个修改器，不会越堆越多；
* 屏幕左下角的状态栏会实时显示「楼梯 N 节 方向」。

> 单位是米，所以体块尺寸按 **Blender 单位**算（默认场景 1 单位 = 1 m；如果你的场景单位不是米，
> 0.3 / 0.2 就是 0.3 / 0.2 个场景单位）。
>
> 自动化测试覆盖：方向→系数映射（含位移太小时不换方向）、方向→轴向（左右 X / 上下 Y）、
> 尺寸换算（阵列轴 0.3、另一条水平轴保持选中前尺寸、Z 恒 0.2）、节数上下限、
> 真实的体块跑一遍（左右与上下两种朝向都验：尺寸、相对偏移、节数、
> **每级位移正好 0.3 m 与下降 0.2 m**、换方向后另一条轴回到原尺寸、重复调用不新增修改器、能删掉）。
> 模态交互本身（鼠标/滚轮手感）无头环境测不了，需要你在 Blender 里拖一下。

### N 面板：三个分页（建模 / 工具 / 主题）

3D 视图 ▸ 按 <kbd>N</kbd> ▸ `红红子lab` 标签页。**标签页里最上面一排就是分页按钮**：

```
┌─────────┬─────────┬─────────┐
│  建模   │  工具   │  主题   │      ← 无标题栏的一行等宽按钮，点了只显示该页
└─────────┴─────────┴─────────┘
```

| 页 | 放的东西 |
| --- | --- |
| **建模** | 四个一键功能（删材质 / 应用修改器 / 删修改器 / **一键楼梯**）+ 「选中 N 个物体 材质槽 X 修改器 Y」+ 「呼出饼菜单」按钮 |
| **工具** | 饼菜单与快捷键、插件设置、**页面布局**、面板顺序（拖动排序） |
| **主题** | 主题颜色（控件配色 / 自定义配色 / 配色预设）+ **字体设置** |

做法参考了插件库里 **ZML_LAB（椎木兰LAB）** 的分页样式，机制完全一样（代码自己写的）：

* 「当前页」是挂在 `WindowManager` 上的一个枚举，**每个窗口各记一份**；
* 标签条是一个 `bl_options = {'HIDE_HEADER'}`、`bl_order = 0` 的面板，只画一行
  `row.prop(..., expand=True)`（`scale_y = 1.35` 加高）；
* 每个功能面板在自己的 **`poll()`** 里判断当前页 —— 不属于本页的面板 Blender 直接不画，
  所以整套功能仍然只占侧栏的**一个**标签页，标签页栏不会变乱。

> 自动化测试覆盖：三页名字与顺序、`WindowManager` 属性已注册到 RNA、
> **切到每一页时 5 个面板的 `poll()` 分别返回什么**（共 15 条断言）、标签条无标题/固定最前/同标签页。

### 主题颜色（N 面板 ▸ 主题 页）

改的是**可互动的控件颜色**，不是工作区/视口配色。每一项都是**分开设置**的：

| 第一级下拉里的分组 | 管的是 |
| --- | --- |
| **按钮 底色** | 按钮的本体颜色（普通按钮 / 工具按钮 / 单复选 / 开关 / 数字框 / 文本输入框 / 菜单 / 饼菜单 / 标签页 / 列表 / 分组框……） |
| **按钮 文字与图标** | 按钮上的**字和图标**颜色（默认浅灰） |
| **按钮 边框** | 按钮的描边 |
| **按钮 选中底色 / 按钮 选中文字 / 按钮 选中边框** | 被选中/按下时的那一套（默认那个蓝） |
| **按钮 高亮** | 滑块、进度条填充、列表高亮条 |
| **图标颜色** | 大纲视图等处按类型上色的图标（物体 / 修改器 / 集合 / 文件夹……） |
| **时间线 当前帧** | 时间线 / 摄影表 / 曲线编辑器 / NLA / 序列 / 影片剪辑 / 图像编辑器 / 3D 视图的**当前帧**指示色与时间轴底色 |
| **状态 / 面板（5.x）/ 视口 / 节点 / 动画** | 已修改、动画、关键帧、驱动器、被覆盖；面板色；视口背景、网格、线框、选中物体…… |

用法：

1. **两级下拉选颜色项**：先在**第一级**选一个**分组**（短词，例如「按钮 底色」「视口」「图标颜色」），
   **第二级**就只列这一组里的项（每组几项到二十几项，标签不再重复拼分组名）——
   一次要画的长列表被拆成两个短列表，弹出框**结构上不再需要截断**
2. 拖颜色选择器 —— **实时生效**
3. 选择器下面有**一行明文读数**（`当前值 #545454  R 0.329  G 0.329  B 0.329`），
   即使下拉框本身显示异常，也一眼能看出选了什么
4. **自定义颜色**：调色盘里挑一个色，或直接填 `#RRGGBB`（填了会自动同步到调色盘），
   再点 **「应用颜色」**
5. 不满意就点 **「恢复本项」** / **「恢复本组」** / **「全部恢复」**（三个范围语义不同，见下）
6. 面板上会实时显示 **「本组 N 项有默认值，已改动 M 项」** —— 如果显示"都还是出厂值"，
   那按恢复当然看不出变化（这不是按钮坏了）
7. **分开设置**：见下一节，每一项旁边都有自己的小调色盘
8. **自定义配色**：起个名字点 `+` 就把当前全部颜色存下来，之后下拉里选中它 → 「套用」/「删除」
9. 满意后点 **「保存到偏好设置」**，否则重启会还原

#### 分开设置：底色 / 图标与文字 / 边框

「控件颜色分开设置」这一块就是解决**"底色统一之后按钮上的图案和字看不清"**的：

1. 先在上面选一个**控件家族**（普通按钮 / 工具按钮 / 菜单项 / 标签页 / 列表行 / 进度条……）
2. 下面**逐项列出该家族的每个颜色，每项右边都有一个小调色盘**，可以直接拖：

| 面板上的行 | 管什么 |
| --- | --- |
| 底色 | 按钮本体颜色 |
| **图标与文字** | 按钮上那些**图标和文字**的颜色（看不清就是这一项要提亮/压暗） |
| 边框 | 描边颜色 |
| 选中底色 / 选中文字 / 选中边框 | 被选中、按下时的那一套 |
| 高亮条/滑块 | 滑块、进度条填充、列表高亮条 |

3. **「自动配文字色」**：按底色的亮度自动挑深色字或浅色字（常态与选中各配一次），
   一键解决看不清的问题；「从当前主题读回」用来在别处改过主题后同步面板
4. 面板底部会**实时检查对比度**：如果某个家族的文字与底色亮度差太小，
   会直接标红提示「字会看不清」，正常则显示"文字与底色的对比度正常"
5. **3 套配色预设也已经成对配好**每个家族的底色与文字色（这个检查会盯着它：
   测试里逐家族断言对比度差 ≥ 0.3，任何一个家族配错都会立刻失败）

> 「恢复本项 / 本组 / 全部」的区别：本项只动你当前选的那一个颜色；本组动当前分组里的全部
> （例如「按钮 边框」这一组的所有描边）；全部则是有出厂默认值的那 60+ 项一起回厂。
> 只有 **4.0.2 与 5.2.2 实测一致**的项才记录默认值，5.x 专属项不记录，避免把 5.x 的默认值套到 4.0 上。

#### 字体设置（主题 页）

在同一个页面的「字体设置」框里，改的是 Blender **偏好设置**里的项（实测 4.0.2 与 5.2.2 属性名一致）：

| 项 | 说明 |
| --- | --- |
| 界面缩放 | 整个界面的缩放倍数（1.0 = 100%） |
| DPI / 字号基准 | 界面字体大小的基准（默认 72） |
| 界面字体文件 | 自定义 `.ttf` / `.otf`（点右边的文件夹按钮选；留空用 Blender 自带） |
| 等宽字体文件 | 文本编辑器等处的等宽字体 |
| 线条宽度 | THIN / AUTO / THICK |
| 文字微调 | 字体 hinting：AUTO / NONE / SLIGHT / FULL |
| 文字抗锯齿 | 关掉更锐利但更难读 |
| 次像素抗锯齿 | LCD 次像素渲染，只对部分显示器有效 |

下面有 **字体恢复默认** 一键回厂。

#### 全局按钮配色（一次改掉所有按钮，含预选中项）

「全局按钮配色」框：给一个**底色**、一个**选中色**，点
**「应用到全部按钮（含预选中项）」**，插件会一次性写入：

* **20 个控件家族**（普通按钮 / 工具按钮 / 下拉菜单 / 菜单项 / 饼菜单 / 标签页 / 列表行 /
  分组框 / 滚动条 / 进度条……）的 **底色 / 图标与文字 / 边框 / 选中底色 / 选中文字 /
  选中边框 / 高亮条** —— 共 140 项；
* **各编辑器里的全局选中高亮**（这些原先不在 wcol 家族里，是"改了主题还是系统蓝"的真凶）：
  `outliner.selected_highlight`（大纲视图选中行，默认偏蓝）、`outliner.active`、
  大纲选中/活动物体、`file_browser.selected_file`、`properties.active_modifier`、
  `info.info_selected`、`text_editor.selected_text`、`console.select`、
  `user_interface.editor_outline` / `editor_outline_active`；
* 文字色默认**按底色亮度自动挑**（深底配浅字、亮底配深字），也可以关掉自动、手动指定；
* 当背景用的那几项（大纲选中行等）会自动用**调暗的选中色**，免得浅色文字压在亮底上看不清。

#### 配色预设

预设一共 **3 套内置 + 1 个自己存的**，在 N 面板 ▸ 主题 页的 **「配色预设（按钮 / 状态 / 当前帧）」**
框里点对应的按钮就套用（三套内置各一个按钮，第 4 个是「自定义预设」；
下面依次是**四个调整滑杆**、「按当前调整重新套用」和「保存当前为自定义预设」）：

| 预设 | 定位 | 主强调色 |
| --- | --- | --- |
| **马拉松 建模 低干扰** | 长期建模的低干扰档：近黑面板 + 压到几乎看不见的边框，黄绿只落在当前选中 / 活动的东西上，不铺开 | 酸性黄绿 `#D6F32B` |

##### 四个调整滑杆（只调强调色，且每个预设各自独立）

四个滑杆**只作用于「强调色集合」**，也就是"变成颜色"的那些地方 —— 当前选中 / 活动的按钮
（每个控件家族的选中底、选中边框、高亮条与滑块）、文本与列表的选中底、活动面板标题、
各编辑器的全局选中高亮（大纲 / 文件浏览器 / 属性 / 信息 / 控制台 / 编辑器图标）、
时间线当前帧、以及**视口里被选中的几何**。**背景、文字、边框、网格线一条都不动。**

这四个值**按预设各存一份**（3 套内置预设 + 「自定义预设」，固定 4 个槽位）：
套用某套预设后，滑杆自动显示**它自己存的那一组值**；调 A 预设的滑杆，B 预设一个字都不变。

| 滑杆 | 范围 | 默认 | 作用 |
| --- | --- | --- | --- |
| **色相** | -180° … +180° | 0°（原样） | 把当前预设的**强调色**整体转一个角度（-180 与 +180 等价）；纯灰（饱和度 0）不受影响 |
| **饱和度** | 0% … 200% | 100%（原样） | `t ≤ 100%`：`S' = S × t`；`t > 100%`：`S' = S + (t-1) × (1-S)`，**200% 正好推到纯色**；纯灰在任何取值下都保持纯灰 |
| **明度** | 0% … 200% | 100%（原样） | `V' = clamp(V × t, 0, 1)`，同样只落在强调色上 |
| **选中线 / 面 饱和度** | 0% … 200% | 100%（原样） | **只作用于视口里被选中的几何**（活动元素 / 顶点 / 边 / 面 四条路径），语义与上面那条饱和度一样 |

* **每个预设各存一份**：四个值不是全局一份，而是按预设分开存（`theme.py` 里
  `preset_hue` / `preset_saturation` / `preset_value` / `selection_saturation` 四个
  `FloatVectorProperty(size=4)`，分量下标 = 预设槽位；面板用 `index=槽位` 直接画）。
  所以"套用 B 会自动显示 B 那一组"是结构上成立的，不靠同步、也不会互相污染；
  默认（0 度 / 100% / 100%）下整表与预设**逐项位级相同**；
  还没套过任何预设时（`last_preset` 为空），四个滑杆按**第一套内置预设**
  （马拉松 建模 低干扰）显示，拖它也就是把那一套按新参数套上 —— 与「按当前调整重新套用」
  的兜底规则一致；
* **集合外的路径是"原对象直接沿用"**：不是"算出来刚好一样"，而是那些键在结果里仍指向
  原来那个颜色元组。有断言逐项核对（三套预设各有 86~115 条护栏路径 × 6 组参数，
  外加真主题里 11 条代表路径的端到端核对）；
* **反复拖不会累积**：每次都是从**预设表**（或你存下来的自定义预设）重算，所以拖到 60% 再拖回 100%
  就是原样，不会越调越灰；
* 「**按当前调整重新套用**」= 用当前预设自己那四个值重新算一遍；
* 「**保存当前为自定义预设**」= 把当前预设的**底表**存成第 4 套，并把当前四个调整值
  **一起固化进「自定义预设」自己的槽位**（同名覆盖，**复用既有的自定义配色存储**，
  不新增配置文件 / 设置项 / 面板）。所以之后套用它 = 底表 + 它自己那份调整 =
  保存当时看到的颜色，**既不会叠加第二次、也不会累积**；源预设的那一份一字不动。
  从没保存过时点「自定义预设」，会明确提示先去保存，而不是莫名失败。

色值集中写在 `theme.py` 的两个调色板字典里（马拉松是 `MARATHON`，旧名 `ACID`；死亡搁浅是
`STRANDING`），想微调直接改 hex 就行（主题里存的就是显示值，`/255` 直接换算）。

预设默认**只改按钮、状态色、时间线当前帧、视口里被选中的几何与视口底色**
（「马拉松 浅灰卡」这一套不改视口底色），并把**基面网格线与法线写回出厂默认值** ——
所以套用后**时间线的当前帧指示也会跟着强调色变**（4.x 上生效；5.x 里 Blender 已经把那些项
删掉了，面板上会自动少掉这一组）。
注意：**套用预设本身**写的是一整张表（含背景 / 文字 / 边框），这是预设的设计；
上面那四个滑杆**只**调其中的**强调色部分**（v2.15.0 起），两者不是一回事。

> **视口里被选中的线 / 点 / 面一律用鲜亮档**（`#D6F32B`），不跟界面控件一起用低饱和档：
> 界面降饱和是为了长时间工作耐看，而"哪些东西被选中"必须一眼看清 —— 上一版把两者一起
> 降饱和，结果就是"被选中的线饱和度太低看不清"。这一条有真机断言守着：4 条视口选中路径
> 的饱和度必须 ≥ 0.6，且**不许等于低饱和档** `#B9CE4E`；同时界面控件（普通按钮 / 分组框 /
> 列表行）必须仍是低饱和档，防止"一改全亮"。**未选中的边、线框、特征标记**（缝合线 / 锐边 /
> 折痕 / 倒角权重）与网格线 / 法线都不受影响。
>
> **颜色到顶之后靠线宽**：调色板里饱和度最高的黄绿就是这个 `#D6F32B`（实测 **0.823**，
> 全表最高，没有更亮的黄绿可换）。所以两套马拉松预设还把**编辑模式选中边的线宽**
> （`view_3d.edge_width`，实测三版 factory-startup 都是 `1`）写成 **2** —— 颜色之外
> 唯一还能提升可见性的手段。它是**尺寸项**（整数、不是颜色），所以「恢复全部」里
> 会有一步把它写回 `1`；想自己改：Blender 的 主题 → 3D 视图 里也能看到它。
> **未验证**：无头环境里看不到画面，这条的实际观感（线是否更清楚）没法自动断言，
> 只实测了"属性存在 + 可写 + 写入后读回一致"。

##### 「死亡搁浅」配色

冷色工业终端观感：**界面控件里蓝是主强调**，橙是点缀（含视口里被选中的几何）。

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 主强调（蓝） | `#4B7FA8` | 控件家族的选中行 / 选中态填充、节点选中（**界面控件仍然是蓝**） |
| 蓝深档 | `#2E4E68` | **需要在其上配浅色文字**的场合：滑块 / 数值框、工具栏图标、工具按钮 |
| 点缀橙 | `#D08A2E` | 面板活动标签，以及「已修改」状态（含其选中态的深一档 `#8A5A1E`） |
| **视口选中橙（高饱和）** | `#E0840B` | 3D 编辑模式里**被选中的几何**：活动元素 / 顶点 / 边 / 面（面是 50% 透明度填充） |
| 常态文字 | `#D6DADE` | 按钮 / 面板上的常态文字，灰白（不用纯白大面积铺陈） |
| 炭黑三级层次 | `#14171A` / `#1C2024` / `#262B30` | 视口与节点背景 / 面板底 / 浮起面板与活动标签（亮度递增，层级做得出来） |

`#E0840B` 是**由点缀橙按公式派生**的，不是新色相：色相沿用 `#D08A2E` 的 **34.1°**，
饱和度从 **0.779 推到 0.950**、明度从 **0.816 抬到 0.880**（抬明度是为了在冷炭黑视口
`#14171A` 上拉开亮度差）。推导：`C = V*S = 0.836`、`m = V-C = 0.044` → `(0.880, 0.519, 0.044)`。
用它的理由：视口里的线又细又压在深色背景上，`0.779` 的橙看着发灰，用户明确要"高饱和的橙色"。
真机断言守着：这 4 条路径的饱和度必须 **≥ 0.9**、必须**等于** `#E0840B`，且与视口背景
（`#14171A` / 面板底 `#1C2024`）的**亮度差 ≥ 0.3**。

**一处刻意的取舍（如实说明）**：选中态填充上用的是**深色文字 `#14171A`**，而不是浅灰白 ——
因为这个蓝在**饱和度降到 40%** 之后三通道互相靠拢、亮度会从 0.4663 升到约 0.586，浅色文字与
它的亮度差只剩约 0.27，达不到项目既有的「文字 / 底色亮度差 ≥ 0.3」；配深色文字则全程都够
（满饱和 0.399、降饱和后 0.519）。这也正是项目既有的"菜单高亮行 = 强调色底 + 近黑字"设计。

橙是点缀不是主色：整套预设里**所有暖色（红 / 橙 / 琥珀）只允许出现在 12 条白名单路径上**
（活动面板标题、已修改状态、关键帧选中、被覆盖、边缝合线、倒角权重，以及**视口里被选中的
几何那 4 条**），多出一条真机断言就会失败；色值一个都不散落在预设函数里，全部来自 `theme.py`
的 `STRANDING` 字典，改那一个字典就能整体换风格。

> 死亡搁浅的视口选中色**已经改过**（用户授权方案 a）：从原来偏冷的蓝 `#4B7FA8`
> （实测饱和度 **0.554**，在灰色模型上不如酸性黄绿醒目）换成**高饱和橙** `#E0840B`
> （饱和度 **0.950**），4 条视口选中路径全部换掉，界面控件的主强调仍然是蓝。

细节说明：

* 覆盖 70+ 项颜色，其中按钮/控件类包括：普通按钮、按钮描边与文字、按钮滑块、工具按钮、
  工具栏图标、单选/复选、开关、单选圈、数字框、数值滑块、文本输入框、菜单项与菜单背景、
  饼菜单、标签页、列表行、提示框、进度条、滚动条、分组框，以及它们各自的**选中态**
  （默认蓝的那一批）；状态色包括已修改 / 有动画 / 关键帧 / 驱动器 / 被覆盖
* **按版本自动过滤**：5.x 才有的 `user_interface.panel_*`、`wcol_state.error/warning/info/success`、
  `wcol_regular.outline_sel` 在 4.0 / 4.2 上不会出现，不需要你判断版本
* 主题颜色内部是 **8 位量化**存储的（写 0.5 读回 128/255 ≈ 0.50196），所以颜色会有极小偏差，这是 Blender 本身的存储方式
* RGB 类颜色项没有 alpha 通道，选择器里的 Alpha 会被忽略（面板上会提示）
* 「恢复默认」用的是 **4.0.2 与 5.2.2 上实测一致**的出厂值；5.x 专属项不记录默认值，
  免得把 5.x 的默认值套到 4.0 上
* 只改颜色，不动主题里的其它设置，也不影响你的主题预设文件

### 页面布局（N 面板 ▸ 工具 页）

把当前的工作区（Layout / Modeling / …）和每个工作区里的**区域划分**（哪个编辑器在哪、占多大）
存成一份带名字的快照，之后在新文件里一键还原。

| 按钮 | 做什么 |
| --- | --- |
| 名字 + `+` | 把当前布局存成这个名字（同名覆盖） |
| **使用** | 把选中的布局套到当前文件：缺的工作区自动补出来并改名，当前工作区里按位置把区域类型改回去；对不上的会如实报告，**不硬拆硬合区域**（那属于高风险操作） |
| **删除** | 从偏好设置里删掉这份布局 |
| **把当前窗口布局设为启动布局** | 把现在的工作区 / 窗口布局写进 Blender **启动文件**；**点之前会弹确认**（会覆盖 `startup.blend`）。新启动文件是**空场景 + 你的工作区布局**，当前场景不会被带进去 |

> 想"新建文件就是这个界面"，用**把当前窗口布局设为启动布局**（下一步有完整步骤）；
> 「使用」按钮管的是**当前文件**。布局存在插件偏好设置里（JSON），跟着偏好设置一起保存。

#### 启动布局怎么用（本版采用手动方案）

> 为什么是"手动方案"：本版 Blender 的脚本接口**删不掉工作区**、也**改不动活动工作区**，
> 这两步只能由你在界面里点一下 —— 详见第 2、3 步里的实测说明。插件不假装能替你做完。

1. **写启动布局**：N 面板 ▸ **工具** 页 ▸ **页面布局** ▸ 点
   **「把当前窗口布局设为启动布局」**（会先弹确认）。它**只写工作区布局**，
   新启动文件是**空场景**（不含当前场景），所以你现在的文件原封不动。
   点之前请先 <kbd>Ctrl</kbd>+<kbd>S</kbd> 保存当前文件（有未保存改动时它会拒绝执行）。
2. **清掉同名的「出厂 xxx」工作区（手动）**：中文界面下出厂启动文件里也有「布局 / 建模 / 着色 /
   UV 编辑」这些**同名工作区**，脚本删不掉它们，插件只能给出厂那份加「出厂 」前缀改名让位。
   实测两条路都不通：`bpy.ops.workspace.delete()` 会**返回成功却什么都没删**（另一种环境里抛
   `GPU API is not available in background mode` 后静默取消），而 `bpy.data.batch_remove()`
   虽然能删，删的若是窗口当前那个会让 Blender **退出时段错误崩溃**（实测 exit=11）—— 所以直接**禁用**。
   想清掉它们：**右键那个「出厂 xxx」工作区标签 ▸ 删除工作区**。
3. **指定"新开 Blender 默认显示哪套布局"（手动）**：新建一个空文件，**用鼠标点一下**你要的那套
   工作区标签，再走 **文件 ▸ 默认 ▸ 保存启动文件**。这一步必须手动 —— 实测脚本改不动当前工作区
   （给 `window.workspace` 赋值不生效），插件不会假装已经替你切过去了。

测试覆盖：JSON 往返（保存 / 列表 / 读取 / 删除 / 坏数据不崩）、空名字拒绝保存、
后台模式（没有窗口）`capture` 返回 None 且 `apply` 明确拒绝、启动布局算符带确认且 `confirm` 默认 False。

### 面板顺序（拖动排序）

N 面板 ▸ `红红子lab` ▸ 顶部切到 **工具** 页 ▸ **「面板顺序」** 面板（它自己固定在最后）：

按住每行左边的手柄上下拖，实时换位，松开确认、<kbd>Esc</kbd> 取消。
顺序存在插件偏好设置里，重启后仍然生效。**这个拖动是真的有效**，因为插件会按你的顺序
**重新注册自己的面板** —— 3D 视图侧栏的先后只看注册顺序（见下面的原理说明）。

下面还列出侧栏里现有的全部标签页（Item / Tool / View / 红红子lab / 其它插件……），
**仅供查看**，不能拖动排序 —— 原因见下。

> **为什么标签页不能排序（实测结论，不是偷懒）**
>
> 1. 想"按住标签页本身拖动"是不可能的：那一列标签由 Blender 的 C 代码绘制并处理鼠标，
>    Python 没有任何钩子可以拦截（社区里要排标签页只能另装 SIMPLE TABS 这类插件）。
> 2. 退一步"用插件帮它重新注册面板来改顺序"这条路**被我实测否决了**：
>    把 Blender 内置或其它插件的面板注销再注册，会直接让 **Blender 4.0.2 与 4.2.23
>    段错误崩溃**（进程退出码 11），5.x 上也会报 `already registered as a subclass 'Panel'`。
>    所以插件只重排**自己**的 5 个面板，绝不动别人的。

> 这些面板全部是**顶层面板**（没有用 `bl_parent_id`）：侧栏 N 面板不保证绘制子面板，
> Blender 自己的 N 面板脚本里一个子面板都没有，所以本插件一律用顶层面板，
> 并由测试静态守住这条（AST 检查类体里不许出现 `bl_parent_id`）。

原理与注意事项（都是实测/查源码得出的，不是猜的）：

* 顺序靠**重新注册面板**实现：3D 视图侧栏的先后由注册顺序决定（实测 Blender 源码
  `interface_panel.cc` 只按插入顺序给面板编号，`BKE_panel_new` 也不读面板类型的 order）。
  插件每次启用 / 拖动后都会按偏好设置重新注册**自己的**面板
* 同时也会写 `bl_order`（官方 RNA 说"数值小的排在前"，但侧栏不读它 —— 图像 / 序列 / 节点
  这些自己排序的编辑器才认），写上无害
* 「本插件的面板」这一项**有自动化断言覆盖**（重新注册成功、面板类都还在、标签页没变少）；
  拖动手感仍需你在 Blender 里实际拖一下确认

### 改快捷键

**偏好设置 ▸ 插件 ▸ 红红子lab**：

* 点 **「按下新按键…」**，然后直接按你想用的键 → 立刻生效（<kbd>Esc</kbd> 取消、<kbd>Backspace</kbd> 恢复默认的 <kbd>Ctrl</kbd>+<kbd>E</kbd>）
* 或者手动改：勾 `Ctrl` / `Shift` / `Alt` / `Cmd`，再填「按键标识」（`E` 就是 E 键、`SPACE` 是空格、`ACCENT_GRAVE` 是 <kbd>`</kbd>）
* 「启用饼菜单快捷键」关掉后，只能用 N 面板呼出

也可以在 **偏好设置 ▸ 键位映射** 里搜索「红红子lab」，用 Blender 自带的方式改键 —— 两种方式是同一个键位。

## 三、每个功能的具体行为（边界情况都处理了）

### 删除所有材质

* 材质槽**一起删掉**，不只是把材质设为空
* **材质数据块本身保留**，不会顺手删除其它物体还在用的材质
* 物体级材质槽（`link == 'OBJECT'`）和数据块级材质槽都会清
* 网格 / 曲线等所有带材质的数据类型都支持；对空物体、灯光、摄像机等不会报错

### 应用所有修改器

* **逐个应用**，保持修改器顺序
* 在视口里被**禁用**的修改器：先临时启用再应用，报告里会说明有几个是这种情况
* **多用户（共享）数据**：自动复制成单用户再应用，不影响共享同一份网格的其它物体
* **带形态键的网格**：Blender 不允许逐个应用，自动改用「转换为网格」一次性烘焙（会丢形态键，无法避免）
* **被隐藏的物体**：临时取消隐藏、做完还原原状态
* **不在当前视图层的物体**（所在集合被排除等）：跳过并在报告里点名
* **曲线/文字上的构建类修改器**：Blender 本身就拒绝应用（提示要转网格），插件会明确报错并**保持原样**，不会偷偷把曲线改成网格
* **链接自其它 .blend 的物体**：跳过并提示

### 删除所有修改器

* 直接丢弃，**不烘焙**，几何不变
* 纯数据操作，不依赖可见性

三个操作都支持 <kbd>Ctrl+Z</kbd> 撤销。

## 四、兼容性与实测

**支持范围：Blender 4.0 及以上**（含 4.x 全系与 5.x）。

所有版本差异都收敛在 [redkolab/compat.py](redkolab/compat.py)：

* 给 `bpy.ops` 注入物体上下文统一用 `bpy.context.temp_override()`
  （4.0 已移除 2.80~3.1 时代的「字典覆盖」写法，所以旧分支已按需求删除）
* 插件偏好设置的 `bl_idname` 用 `__package__`：传统安装是 `redkolab`，
  4.2+ 扩展安装是 `bl_ext.<仓库>.redkolab`，写死字符串必挂
* 属性一律用**类型注解**写法（`key_type: StringProperty(...)`），
  赋值写法在 4.0+ 上根本不会生成 RNA 属性

同一份 `redkolab-2.15.0.zip`，真机无头测试：真的装包、真启用、真建场景、真跑功能并断言。

## 六、自动发布与归档

打一个 tag，就会自动完成「打包 → 自检 → 多版本真机测试 → 发布 → 归档」：

```powershell
powershell -ExecutionPolicy Bypass -File tools\release.ps1 -Bump patch
```

这条命令依次做：检查工作区干净 → 升版本号（`bl_info` 与 `blender_manifest.toml` 一起改，永远同步）
→ 版本一致性检查 → 打包 → 安装包结构自检 → **复制进本地插件 zip 库并替换旧版本**
→ 提交 → 打 `v<版本>` tag（如 `v2.12.1`）→ 推送（带重试）。
任何一步不过就直接中止，不会把坏包推上去。加 `-DryRun` 可以只看检查结果不推送。

**本地插件 zip 库**默认是 `D:\build\Blender\4.0\4.0chajian`（放 Boxcutter / HardOps / MACHIN3tools
这类安装包的地方）：每次发版会把新的 `redkolab-<版本>.zip` 复制进去，并删掉里面的旧版本
（只删该目录下匹配 `redkolab-*.zip` 的文件，别的插件包与文件夹一律不碰）。

**已安装副本**默认是 `%APPDATA%\Blender Foundation\Blender\4.0\scripts\addons`：每次发版会把
`redkolab\` 整个替换成新版本的内容，这样 Blender 下次启动加载的就是最新的
（**装完记得重启 Blender**，或停用再启用插件）。想换目录用 `-DeployTo` / `-InstallTo`，
不想动本地用 `-NoDeploy` / `-NoInstall` 跳过，想留历史 zip 用 `-KeepOld`：

```powershell
powershell -ExecutionPolicy Bypass -File tools\deploy_local.ps1 -Target "D:\其它\插件库" -InstallTo "D:\其它\addons"
```

推送后 [.github/workflows/release.yml](.github/workflows/release.yml) 自动执行：

| 阶段 | 内容 |
| --- | --- |
| 打包自检 | tag 与源码版本一致性、打包、结构自检（布局 / 元数据 / 属性写法 / 上下文覆盖）、生成 SHA256SUMS.txt |
| 真机测试 | 下载 Blender **4.2 / 4.5 / 5.2**（首次下载后走缓存），在隔离的配置目录里真装真跑 800+ 项断言；5.2 上再额外走一遍扩展页安装入口 |
| 发布归档 | 建立 Release，把 `redkolab-<版本>.zip` 与 `SHA256SUMS.txt` 作为附件永久归档 |

**任何一步失败都不会发布** —— 不会出现版本号对不上的包或装不上的包被归档。

只想构建和测试、不发版：仓库页 ▸ Actions ▸ Release ▸ Run workflow（手动触发不发 Release）。

## 七、已知限制

* 编辑模式下按钮是灰的（Blender 不允许在编辑模式改动材质/修改器数据），面板会提示切回物体模式
* 饼菜单的「按下新按键…」捕获需要真实窗口，无法在无头环境自动化测试，其余功能都有自动化覆盖
* 曲线的构建类修改器无法应用（Blender 的限制，见上文）
* 「应用所有修改器」遇到形态键会丢失形态键（转换烘焙的固有代价）
* 主题颜色按 8 位量化存储，写入值读回会有约 1/255 的偏差（Blender 本身的存储方式）
* RGB 类主题颜色项没有 alpha 通道，颜色选择器里的 Alpha 会被忽略
* 主题改动立即生效，但想重启后保留需要点「保存到偏好设置」（或正常退出 Blender 让偏好自动保存）
* 5.x 独有的 `user_interface.panel_*` 颜色项在 4.0 / 4.2 上会自动隐藏（不是 bug）
* 面板顺序的**拖动手感**无法在无头环境自动化验证（重新注册的机制有断言覆盖）
* **侧栏的标签页不能排序**：一是标签栏由 Blender 的 C 代码处理、Python 没有钩子；
  二是"帮它重新注册面板"这条路实测会让 Blender 4.0 / 4.2 段错误崩溃。
  「面板顺序」面板里只列出标签页供查看
* 默认快捷键 <kbd>Ctrl</kbd>+<kbd>E</kbd> 在**编辑模式**下会与 Blender 的「边」菜单冲突（Blender 优先），
  所以饼菜单在编辑模式下不弹出；偏好设置里可以随时换成别的键
* **侧栏的标签页本身没法用鼠标拖动排序**：那部分是 Blender 的 C 代码绘制并处理鼠标的，
  Python 没有钩子（社区里排标签页也要另装 SIMPLE TABS 之类插件）；而用重新注册面板的方式
  去改别的插件的顺序，实测会让 Blender 4.0 / 4.2 崩溃，所以本插件不做这件事
* **颜色项下拉可能出现乱码**（只有那个弹出条目框，面板其它中文正常）—— 本版改成两级短选择
  从**结构上消除长列表**，见下面一小节
* 两级选择器只是"把长列表拆成两个短列表"的**结构性**改动：弹出框绘制层的实际观感
  （还有没有截断/乱码）**无头环境测不了**，需要你在 GUI 里看一眼 —— 这一条如实标注为未验证
* 「自定义预设」是**覆盖式**的（同名保存即覆盖）；界面上没有单独的"删除自定义预设"按钮
  （它和「自定义配色」共用同一份数据，但不出现在那个下拉里，避免看到一个自己没起过的名字）
* 「自定义预设」的**强调色集合**是"三套内置预设共同认作强调色的那批槽位"（它的色表是一份快照，
  没有工厂可以在写的时候登记路径）。取交集而不是并集，所以**只会少几条、不会把背景色算进来**：
  只有某一套预设才当强调色用的路径（如死亡搁浅的「节点编辑器选中节点」）落在交集之外，
  拖滑杆时它不会跟着变色 —— 想要它跟着变，请在那套内置预设上调，或直接用「逐项微调」单独改它
* 四个调整值的**用户可见语义**（只调强调色、每个预设各存一份）在无头测试里是逐项断言的，
  但"拖动手感"本身仍需在 GUI 里体验
* 许可证：GPL-3.0-or-later（Blender 插件的通行许可）

### 故障排查：颜色项下拉出现乱码怎么办

**现象**：N 面板 ▸ 主题 页 ▸ 进阶 ▸「逐项微调」里的**颜色项下拉**，弹出的条目显示成
`¤C` / `°ðC` 这类乱码，而同一个面板的其它中文（「逐项微调」「颜色项」「自定义配色」）正常，
鼠标悬停提示气泡里的路径（`user_interface.wco…`）也正常。

**结论：不是数据坏了**（包里的源码是合法 UTF-8、无 BOM，按 UTF-8 解码「底色」这类中文完全正常），
而是那个**弹出条目框的绘制层**问题：条目一多，列宽有限，Blender 会把放不下的条目标签
**按像素宽度从中间截断**（`interface_widgets.cc` 里的 `text_clip_middle` / `text_clip_middle_ex`），
中文字被切在半个字上时，落单的多字节会被画成乱码 —— 那个函数里就留着
`TODO: proper handling of non UTF8 strings` 的注释，说明 Blender 自己也承认这条路径对非 ASCII 不完善。

**2.14.0 的做法：两级短选择，从结构上避免"长列表被截断"** ——

1. **第一级**选**分组**（短词，本版本最多 21 组，最长 6 个字）；
2. **第二级**只列这一组里的颜色项（每组 4～24 项，标签不再重复拼分组名，最长的第二级列表
   也从原来的 200+ 项降到二十几项）。

也就是说：**一次要画的长列表没有了**，弹出框不需要为了列宽去截断那么多条目。
「恢复本项 / 本组 / 全部」、调色盘、「应用颜色」、明文「当前值」这些链路一个都没动
（第一级的分组就是「恢复本组」用的那个分组）。

> **这是"结构性消除长列表"，不是"乱码已修复"**：那个弹出框的**绘制层**在无头环境里测不了，
> 所以本版只断言了"结构上不会再有 200+ 项的长列表""每条可用路径都能被两级选到"
> （可达集合 == 可用集合），**实际观感仍需你在 GUI 里看一眼**。
> 如果换成两级之后仍然偶发乱码，那说明根源在你的界面字体或 Blender 的绘制层，可继续试下面两步：

1. **打开「简洁模式」**（主题页里的开关）：每一组里的项再减少一批，弹出框更短；
2. **清空自定义界面字体**：`编辑 ▸ 偏好设置 ▸ 界面 ▸ 界面字体` 把文件路径清掉（改用 Blender 自带字体）再看一次 ——
   自定义字体缺字或字宽异常时，这类截断问题更容易暴露。

另外两条不受影响的路子：

* 改某个**家族**的整组颜色，用「**控件颜色分开设置**」（家族 + 7 个部位：底色 / 图标与文字 / 边框 /
  选中底色 / 选中文字 / 选中边框 / 高亮条，中文显示正常）；
* 想按路径逐个核对，看鼠标悬停的提示气泡，或用「全局按钮配色」「自定义配色」这两块。
